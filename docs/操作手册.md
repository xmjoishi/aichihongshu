## 1. 初始化环境

### 1.1 克隆项目并初始化

```bash
git clone <repo-url>
cd RN-家居类

# 构建 Rust CLI（无需 Python/uv，也无需初始化 MediaCrawler 子模块）
cargo build --locked --manifest-path client/rn/Cargo.toml

# 将本次构建的 rn 加入当前终端 PATH
export PATH="$PWD/client/rn/target/debug:$PATH"
```

### 1.2 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env`，填入：

```env
MINIMAX_API_KEY=sk-cp-...            # 必填，Token Plan Key（注意格式 sk-cp-）
MINIMAX_BASE_URL=https://api.minimaxi.com/anthropic   # 文本生成接口（兼容 Anthropic SDK）
MINIMAX_VISION_MODEL=MiniMax-Text-01  # 仅作标记，图片分析走固定的 /v1/coding_plan/vlm
MINIMAX_TEXT_MODEL=MiniMax-M2.7
```

> **重要**：MiniMax 有两种 API Key 格式：
> - 按量计费 Key：`eyJhb...`（JWT 格式）
> - Token Plan Key：`sk-cp-...`
>
> 本项目图片分析使用 `/v1/coding_plan/vlm` 原生接口，**必须使用 Token Plan Key**（`sk-cp-` 开头）。两种 Key **不互通**，填错会报 401。
>
> MiniMax Token Plan 申请：https://platform.minimaxi.com/

### 1.3 初始化数据库

```bash
rn db init --yes
```

默认数据库为 `data/app.db`。首次创建时显式传入 `--yes`；也可以使用 `--db <路径>` 指定隔离数据库。

## 3. Step 0：初始化我的账号人设

**目的**：存储运营主体（你的账号）的人设信息，这些信息会自动注入所有笔记生成 Prompt，确保内容语气一致、不使用禁忌词。**首次必做，影响所有后续内容创作。**

### 3.1 方式一：同步主页并推断（推荐）

提供自己的账号主页 URL，Rust worker 会在该运营账号独立浏览器会话中读取可见主页和最近笔记，再用 AI 尝试推断垂类定位、语气风格、话题标签等字段：

```bash
# 首次运行会打开独立浏览器；请手动登录并处理平台验证
rn profile init \
    --url "https://www.xiaohongshu.com/user/profile/<你的账号ID>"
```

执行后会：
1. 读取主页上已显示的资料与最多 30 篇笔记
2. 用 MiniMax AI 分析笔记内容，推断账号人设字段
3. 打印推断结果，并写入数据库

推断完成后，补充爬虫无法自动获取的字段（如人设名、个人简介）：

```bash
rn profile edit \
    --persona-name "虾薯" \
    --persona-bio "住出租屋也要好看的家居研究员"
```

也可以在 `init --url` 的同时手动覆盖 AI 推断的字段：

```bash
rn profile init \
    --url "https://..." \
    --persona-tone "嘴硬傲娇，短句换行，先吐槽再给结论" \
    --taboos "精致,高品质,高级感"
```

### 3.2 方式二：手动填写

如果没有账号或不想爬取，直接手动填写：

```bash
rn profile init \
    --name "账号显示名" \
    --niche "家居软装/出租屋改造" \
    --persona-name "虾薯" \
    --persona-bio "住出租屋也要好看的家居研究员" \
    --persona-tone "嘴硬傲娇，短句换行，先吐槽再给结论" \
    --taboos "精致,高品质,高级感,氛围感" \
    --styles "奶油风,侘寂风" \
    --scenes "客厅,卧室,出租屋" \
    --hashtags "家居好物,软装分享,出租屋改造,装修日记"
```

### 3.3 查看当前人设

```bash
rn profile show
```

### 3.4 更新单个字段

```bash
# AI 推断结果不准确时，手动修正
rn profile edit --persona-tone "直白干脆，多用反问，先给结论再解释"
rn profile edit --taboos "精致,高品质,高级感,氛围感,质感"
rn profile edit --niche "出租屋软装改造/平价家居好物"

# 更新账号数据
rn profile edit --followers 1000
```

## 4. Step 1：录入榜样账号

**目的**：录入家居垂类做得好的账号，其风格数据会在 Step 3 生成 Prompt 时作为参考输入。

### 4.1 方式一：手动录入（推荐）

适合已经手动调研过的账号，直接填入关键数据：

```bash
rn accounts add <account_id> \
    --name "账号名" \
    --note-count 80 \
    --avg-likes 5000 \
    --avg-comments 150 \
    --avg-collects 1200 \
    --style "内容风格描述，如：走性冷淡极简路线，标题多用反问句，正文短段落" \
    --top-notes "高赞标题1,高赞标题2,高赞标题3"
```

`<account_id>` 从小红书账号主页 URL 中取：`https://www.xiaohongshu.com/user/profile/<account_id>`

### 4.2 方式二：同步榜样主页

在桌面客户端「榜样」页选择「导入账号」，输入主页链接并确认采集。应用使用当前运营账号的独立浏览器会话，最多读取页面已显示的 30 篇笔记；链接中的临时访问参数不会保存。登录或平台验证时，请在打开的浏览器窗口中手动处理。

### 4.3 管理榜样账号

```bash
# 列出所有账号
rn accounts list

# 查看账号详情
rn accounts show <account_id>

# 删除账号
rn accounts delete <account_id> --yes
```

## 5. Step 2：图库管理

**目的**：建立图库，每件物品自动通过 MiniMax 分析，提取风格/材质/卖点等字段，作为后续内容创作的原材料。

### 5.1 导入单张图片

```bash
rn library add ./my-chair.jpg --title "奶油色布艺椅"
```

执行后会：
1. 将图片复制到 `assets/` 目录统一管理
2. 调用 MiniMax `/v1/coding_plan/vlm` 接口分析图片
3. 自动写入数据库（风格、材质、颜色、场景、话题标签、搭配建议、小红书卖点）

**输出示例**：
```
正在分析图片... ./my-chair.jpg
✓ 分析完成：布艺休闲椅 / 北欧简约
✓ 已添加物品 ID=1：奶油色布艺椅
  风格：北欧简约  材质：布艺+实木腿  颜色：米白
  场景：卧室/书房
  卖点：慵懒的坐感 / 治愈米白色 / 腿部实木细节
```

### 5.2 批量导入

```bash
# 逐个导入（暂无批量命令，v0.2 规划中）
for f in ./products/*.jpg; do
  rn library add "$f"
done
```

### 5.3 管理图库

```bash
# 查看所有物品
rn library list

# 按风格筛选
rn library list --style 北欧

# 查看详情
rn library show 1

# 手动补充标签
rn library tag 1 --add "性价比"
rn library tag 1 --add "出租屋友好"
```

### 5.4 跳过 MiniMax 分析

如果暂时没有 Token Plan Key，可先跳过分析直接入库：

```bash
rn library add ./my-chair.jpg --title "布艺椅" --no-analyze
# 后续在数据库中手动补充字段，或获取 Key 后重新分析
```

## 6. Step 3：生成笔记 Prompt（Skill 驱动）

**目的**：针对某件具体物品，生成完整的笔记创作 Prompt（含人设、物品分析、参考账号风格），粘贴给 Agent 生成内容。

### 6.1 生成 Prompt

```bash
# 基本用法（自动读取 my_profile 人设）
rn content draft <item_id>

# 指定参考账号风格（Prompt 中加入参考账号的内容风格描述）
rn content draft <item_id> --account-id <account_id>

# 添加额外创作要求
rn content draft <item_id> \
  --account-id <account_id> \
  --extra "这次主要打性价比角度，强调出租屋也能用" \
  --save   # --save 会在数据库创建 draft 状态的笔记记录，打印出 note_id
```

> 如果尚未执行 `profile init`，命令会给出警告并使用默认风格。建议先完成 Step 0。

### 6.2 将 Prompt 发给 Agent

将命令输出的 Prompt **完整复制粘贴到 OpenCode 对话**中。当前 session 已加载 `xiaohongshu-ops` skill，Agent 会按 skill 的 persona 和内容框架生成：

```
---标题候选（3 个）---
情绪型：买了这把椅子，出租屋也有了家的感觉
问题型：为什么我的椅子比朋友的贵一倍，但没好看一倍？
场景型：卧室角落放一把它，每天下班第一件事

---封面文案---
花 300 配出 3000 的感觉

---正文---
（第 1 段·钩子）
搬进新家的第一周，总感觉卧室差点什么...

（第 2 段·核心体验）
...

（第 3 段·搭配代入）
...

---互动引导---
你们卧室有没有这种「角落椅」？来评论区晒一下

---话题标签---
#家居好物 #软装搭配 #卧室布置 #北欧风 #布艺椅 #出租屋改造
```

> **Skill 参考**：
> - `persona.md` — 虾薯人设，傲娇嘴硬风格，短句换行，不说空话
> - `SKILL.md §4` — 通用内容模板
> - `references/xhs-home-feed-analysis.md` — 可复用结构模式

## 7. Step 4：填入内容

### 7.1 将 Agent 生成内容填入数据库

```bash
rn content edit <note_id> \
  --title "买了这把椅子，出租屋也有了家的感觉" \
  --body "搬进新家的第一周，总感觉卧室差点什么...（完整正文）" \
  --cover "花 300 配出 3000 的感觉" \
  --tags "家居好物,软装搭配,卧室布置,北欧风,布艺椅,出租屋改造" \
  --status ready
```

> `note_id` 是 `content draft --save` 时打印出来的 ID。如果没加 `--save`，先运行 `content list` 找到对应记录。

### 7.2 查看笔记

```bash
rn content list
rn content list --status ready
rn content show <note_id>
```

## 8. Step 5：导出与发布

### 8.1 导出 Markdown

```bash
# 打印到终端
rn content export <note_id>

# 保存到文件
rn content export <note_id> --output ./drafts/note-001.md
```

### 8.2 发布到小红书

目前发布为手动操作。后续版本（v0.2）规划接入 OpenClaw 自动化发布。

手动发布步骤：
1. 打开 [小红书创作者后台](https://creator.xiaohongshu.com/)
2. 点击「发布笔记」→「上传图文」
3. 上传 `assets/` 中对应的图片
4. 粘贴导出的标题、正文、话题标签
5. 发布前检查三要素：封面、标题（≤20字）、正文

> **Skill 参考**：`references/xhs-publish-flows.md` — 详细的图文/视频/长文发布 SOP

### 8.3 发布后更新状态

```bash
rn content edit <note_id> --status published
```

### 8.4 移动端 App 快捷流程（iOS）

手机上的推荐路径（与 CLI 可并行）：

1. **素材库**：授权相册 → 点图入库（自动 AI 分析）→ 可筛选「已分析/未分析」、长按多选批量分析。
2. **创作**：底部「创作」→ 右上 `+` 进编辑 →「加图」→ **一键生成**（可填主题提示词，可空）→ 人工改稿 →「存草稿」或「下一步 · 发布准备」。
3. **AI 创作**（可选）：素材库右上「AI 对话」可带图追问；时钟图标看历史会话；返回会回到素材库。
4. **发布准备**：复制标题 / 正文+话题；预览图与笔记全文；「分享 N 张图到小红书」或备用「导出到相册」；完成后点「发布完成」。

**注意**：未点「存草稿」不会写库；空白草稿返回即丢弃。相册导出需在系统设置允许「添加照片」。Expo Go 下多图一次进分享面板受限，需 dev build。

### 8.5 桌面端浏览器剪藏与单篇快照

1. 在桌面端打开「设置 → 通用 → 浏览器剪藏与快照」，安装/更新 Native Messaging 宿主，并在 Chrome/Edge 加载扩展目录。扩展与宿主就绪后，桌面端需要保持运行且当前账号已就绪；无需停留在某个业务页。
2. **收藏网页**：建议在已登录的小红书网页中打开目标笔记后剪藏；分享链接也可用，但需先确认它能在当前浏览器正常打开。点击扩展，检查预览和当前账号，选择「收藏内容」后点「收藏到素材库」。桌面端先将文字收藏写入当前账号本地数据库，再在后台尝试保存本次明确勾选的图片；未勾选图片不会下载。图片逐张显示本地化状态，失败不影响已保存正文，也不会把部分成功显示成全部成功。旧版本遗留的待确认剪藏会在首次打开网页收藏页时迁入卡片。
3. **更新单篇数据**：优先从已登录的桌面网页直接打开目标笔记，再点击扩展并选择「更新数据」。分享链接里的渠道、设备和跟踪参数不提升刷新可靠性；访问权限或登录状态失效时，应从小红书站内重新打开。先检查标题和互动数据预览，再执行。指标缺失时会保留为空；以桌面端显示的快照保存结果为准。
4. 网页收藏使用瀑布流卡片；本地化后的首图作为封面，图片和缩略图从当前账号的本地受管目录读取。打开卡片可查看正文、作者、已选评论并轮播图片，支持方向键切图、放大和 Escape 关闭。支持搜索标题、正文、作者、来源和标签，按来源/时间/标签筛选，也可编辑自己的备注与标签、取消收藏、转为草稿。加入创作素材需要在详情中明确点击；普通收藏不会自动进入创作素材库。旧收藏会按需把已有图片 URL 补成本地附件；链接失效时可以回到原文重新采集。小红书笔记按路径中的笔记 ID 去重，因此分享链接和网页直开链接即使参数不同也会归并到同一条笔记。

扩展只在用户点击后读取当前标签页，不批量打开链接，也不后台定时抓取。账号切换前先确认当前激活账号，剪藏与数据快照都会归属到该账号。

## 9. 补充：关键词搜索分析

此步骤为可选补充，用于了解平台当前家居类热门内容结构，提取可复用的钩子词和标题骨架。

### 9.1 关键词搜索抓取

```bash
# 首次运行会打开隔离的受控浏览器；登录或安全验证时按提示手动处理
rn search \
  --keywords "家居好物,软装搭配,装修分享" \
  --count 30 --save-db
```

搜索结果以 JSON 保存到 `data/crawl/`；采集只读取页面已展示的笔记，并限制滚动与结果数量。

### 9.2 生成分析报告

```bash
rn analyze \
  --input data/crawl/搜索结果.json \
  --keywords "家居好物,软装搭配,装修分享" \
  --save-db
```

分析报告会写入 `data/analysis/`，终端同时显示互动概览、钩子词和高互动样本。

### 9.3 深度分析（Skill 驱动）

将分析报告粘贴给 OpenCode：

```
帮我分析小红书家居类首页推荐流，这是最近的抓取数据：

[粘贴 `rn analyze` 的终端输出]

账号方向：家居好物分享，家居爱好者人设，重点聚焦软装搭配
```

## 10. Skill 使用指南

`xiaohongshu-ops` skill 安装在 `~/.config/opencode/skills/xiaohongshu-ops/`，在 OpenCode 对话中自动加载。

### 10.1 Skill 与本项目的协作关系

| 本项目 CLI | Skill 提供 | 如何协作 |
|---|---|---|
| `content draft` | persona + 内容框架 | CLI 生成 prompt → 粘贴给 Agent → Agent 按 skill 规则输出 |
| `rn analyze` | 首页推荐流分析框架 | 搜索输出 JSON → 生成报告 → 粘贴给 Agent 按 xhs-home-feed-analysis 分析 |
| `rn profile init --url` | 账号主页同步与人设推断 | 受控浏览器读取可见主页数据；Agent 可继续按 xhs-account-analysis 输出风格分析 |
| 手动发布 | 发布流程 SOP | 参考 xhs-publish-flows.md 的图文发布步骤 |

### 10.2 Skill 核心文件速查

## 12. 常见问题

**Q: `library add` 报错 "Token Plan API Key 无效" 或 401？**

A: 确认 `.env` 中的 `MINIMAX_API_KEY` 是 Token Plan Key（`sk-cp-` 开头），不是按量计费 Key（JWT 格式 `eyJhb...`）。两种 Key 不互通。前往 https://platform.minimaxi.com/ 申请 Token Plan。

**Q: MiniMax 分析报错 "缺少 MINIMAX_API_KEY"？**

A: 检查项目根目录 `.env` 文件是否存在且已填写 `MINIMAX_API_KEY`。

**Q: `library add` 分析成功但字段为空（`—`）？**

A: MiniMax 返回的 JSON 解析异常。检查 `data/app.db` 中 `items.analysis_raw` 字段的原始内容，确认是否为有效 JSON。可用 `library tag` 手动补充标签。

**Q: `content draft` 提示"尚未初始化账号人设"？**

A: 先执行 `profile init` 初始化人设（见 Step 0）。命令会在没有人设时使用默认风格并给出警告，但建议填写真实人设以确保笔记语气一致。

**Q: `content draft` 的 Prompt 风格不对，如何调整？**

A: 通过 `profile edit --persona-tone "..."` 更新语气描述，或 `profile edit --taboos "词1,词2"` 更新禁忌词。这些变更会立即反映在下一次 `content draft` 的输出中。

**Q: 搜索运行后没有数据，或者提示需要登录？**

A: 搜索使用账号池管理的独立浏览器会话，不读取旧 MediaCrawler Cookie。先在桌面「账号池」打开对应账号的浏览器并手动登录；然后运行 `rn search --keywords "家居,软装,装修" --count 20 --save-db`。命令只读取搜索页已显示的卡片，最多每个关键词 50 篇，并将 JSON 保存到 `data/crawl/`。登录失效或平台验证时按提示在浏览器里手动处理后重试。

**Q: Skill 有更新，如何同步？**

A: 在 OpenCode 对话中输入：`帮我安装最新版 xiaohongshu-ops skill`
