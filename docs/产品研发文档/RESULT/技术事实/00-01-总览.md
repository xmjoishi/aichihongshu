# 技术事实总览

## 移动端发布分享直发（CHG-20260925-004，2026-09-26 验收）

- `react-native-share@12`：`Share.open({ urls, message })` 多图一次唤起系统分享面板；`ph://` 经 `resolveLocalUri` 转 `file://`；用户取消 `failOnCancel:false` 归一为 `dismissed`。
- 分享 payload：`message` = 正文+话题（不含标题）；`title` 传笔记标题供目标 App 参考；触发时 `expo-clipboard` 写入同款文案兜底。
- 打开小红书：候选 `xhsdiscover://post_note` / `post` / `xiaohongshu://` / `xhsdiscover://` / `xhsdiscovery://`，失败兜底 `https://apps.apple.com/cn/app/id741292507`；iOS 需 `LSApplicationQueriesSchemes`（xhsdiscover/xiaohongshu/xhs/xhsdiscovery）才能可靠 `canOpenURL`，现实现直接 `openURL` + try/catch。
- AI 带图：`chat({ images: base64[] })` 多模态，`resolveModelId` 自动回退视觉模型；编辑页 callAi 附最多 6 张关联图。

## 移动端编辑页图片条（CHG-20260925-005，2026-09-26 验收）

- 拖动排序：`react-native-gesture-handler` Pan + `activateAfterLongPress(180)`，Reanimated shared value 驱动拖起项与让位位移；根布局需 `GestureHandlerRootView`（`app/_layout.tsx`）。
- 删除按钮必须放在 `GestureDetector` 外侧，否则点 × 会误触拖动手势导致图片放大。
- 预览类界面（全屏看图 / 笔记预览 / 封面预览）合并为**同一 Modal** 内按优先级条件渲染——iOS 上多个 Modal 叠加会出现下层点了没反应、关闭后被回调“复活”的问题。
- 图片条加图先暂存在编辑页状态中，保存笔记或实际用于 AI 时才通过 `recordAssetUse` 创建/复用照片元数据行；不复制原图。系统照片优先以平台 asset ID 关联，URI 作为读取/回退引用。
- 占位资源：`mobile/assets/logo.png`（LOGO/v2.8/mark.png），昵称写死「小红薯」待接账号。


## 移动端体验与 AI 创作一批（2026-09-27 验收，未建 CHG）

- `resolveLocalUri` 使用完整 `ph://<localIdentifier>`（含 `/L0/001`），进程内 Map 缓存；展示前需解析为 `file://`（New Architecture 无 `ph://` Image loader）。
- 送识别前嗅探图片魔数；HEIC/未知格式经 `expo-image-manipulator` 转 JPEG（长边≤1600）；`media_type` 按真实格式标注。
- `analyzeImage` 走配置 provider 的 `chat()` 多模态通道；返回空字符串抛错；失败在 UI 可见。
- 文案清洗：`mobile/utils/xhsText.ts` 的 `stripMarkdownForXhs` / `extractTitleAndBody`。
- 会话历史：`mobile/services/chatHistory.ts` 写 `documentDirectory/chatSessions/*.json`。
- 瀑布流分页：`loadNotes`/`loadMoreNotes`，`NOTES_PAGE_SIZE=12`；筛选在已加载集合内过滤。
- 导出相册：申请 writeOnly 权限；`ph://` 优先挂已有 Asset，失败走 `saveToLibraryAsync`。
- 导航：对话页 `dismissAll` + `from=library` 时回相册，避免创作 Tab 栈残留。

## 移动端照片引用第七轮（CHG-20260925-005，2026-09-27 实施中，待用户验收）

- `items.source_asset_id`、`used_at`、`usage_sources` 保存平台照片引用和使用元数据；`items` 只包含实际使用或保存为笔记关联的照片，不扫描全图库入库。
- 相册页展示系统权限可见照片，并用 `已入库/已分析/未分析/已使用` 筛选；这些状态是可重叠维度。未分析只统计有应用记录且无分析结果的照片。
- 照片列表每页读取 36 张，仅可视照片尝试从 iCloud 读取原图；相册获焦、系统照片变化、权限选择器关闭后刷新首屏。
- AI 对话、编辑页、多选分析/笔记、PC Harness 都只在照片实际提交到对应功能时建行或追加使用来源；撤权/删除后保留应用元数据，`PhImage` 显示原图不可访问提示。


## PC 工作区性能实现（CHG-20260921-002，2026-09-28 验收）

- 页面实例按账号与首级菜单保留；隐藏页面停用普通查询、轮询、页面快捷键和上下文发布，显示时按 React Query 缓存状态补读。AI 流和编辑保存生命周期单独保持。
- 本地工作区快照按 library、notes、profile、references、summary、workspace 分段，并以账号作用域共享缓存；写操作按资源前缀失效缓存。
- 素材网格只渲染可见行及预留行。本地图片通过共享可见性观察和最多四个并发读取；内存缓存上限 128 项及估算 32 MiB。离屏组件释放其图片 URL 状态。
- 图片读取、模型连接/列表请求、OpenCode 模型扫描使用后台阻塞任务；联网和模型扫描设有超时。
- 前端构建、Rust 编译和格式检查通过；用户确认 AC-22–24 原生验收通过（2026-09-28）。
