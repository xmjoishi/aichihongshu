### 产品范围

1. **独立一级「剪藏」**：剪藏对象分为外部账号、笔记、素材。外部账号是作者主页资料，不等于本地运营账号，也不会自动成为榜样；笔记同时支持小红书图文与普通网页文章，并明确来源；素材单独保存图片等当前已支持文件，不自动成为创作素材。其他模块可引用剪藏对象；详情提供适用的显式动作，例如设为榜样、作为参考、加入选题、转为草稿、加入创作素材。取消一个引用不得删除仍被其他对象使用的对象或文件。旧收藏、榜样、分析、标签、备注和本地账号边界都要无损兼容。
2. **原图随剪藏落地**：不假设扩展可读浏览器缓存，不用截图替代原图，不导出 cookie。笔记/素材中已选的图片必须在剪藏完成前将真实字节落到当前桌面账号的本地受管目录。保存时先按精确 HTTPS 来源域申请可选权限，并只在扩展 service worker 以不带凭据请求所选图；权限拒绝、跨域/登录限制、不可读 blob 或不支持类型时逐项说明。传输采用有界分块、顺序、SHA-256、requestId、通道/工作区/账号校验及幂等恢复。沿用既有原图/缩略图签名、尺寸和安全路径校验。不得增加常规剪藏的 Rust 后台 URL 下载。只含 URL 的旧数据保留明确的一次性补全入口。
3. **扩展内容优先**：笔记场景左侧图片轮播与缩略图勾选；默认勾选所有已识别可保存图，可单张取消、全选、清空。右侧呈现标题、作者、来源、正文和页面可可靠识别的赞藏评转；无法识别的值显示未知。标题/作者/来源默认保存；评论默认关闭并在展开后选择。底部将唯一主按钮标为“保存到剪藏 · 笔记 / 保存笔记和 N 张图片”；已有对象显示已剪藏和明确的更新正文或刷新数据动作。主页显示头像/昵称/简介/账号指标，正文区域不混入主页笔记；“选择笔记”是独立动作。素材场景单独显示图网格和“保存 N 张素材”。连接区仅显示目标和状态，协议/工作区诊断折叠；自动识别页面类型并提供识别有误的调整入口；保留正式/DEV 显式选择、断连暂存和原 requestId 核实。
4. **桌面阅读与引用**：一级剪藏页以内容、分类、搜索和引用动作为中心，使用本地附件封面和自然高度瀑布流；无图卡紧凑。详情阅读优先，显示作者、标题、正文、话题/互动、已选评论，备注标签按需编辑；显示真实本地运营账号名称与被采集作者的区别。图片断网可读，空图、传输中与失败可辨识。以可复用引用连接现有笔记、榜样与创作素材，删除引用不级联删除共享文件。

## 浏览器取图可行性证据

- [Chrome `activeTab`](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab)：扩展被用户唤起时临时授予活动标签主 frame 来源；不授予任意 CDN 域。
- [Chrome cross-origin requests](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)：内容脚本请求仍按页面源执行同源限制；扩展 service worker/页面在有相应 host permission 时可以跨源 fetch。
- [Chrome optional permissions](https://developer.chrome.com/docs/extensions/reference/api/permissions)：可在用户手势中申请运行时权限；可选来源通过清单声明，再按发现的来源传给 `permissions.request`。
- [Chrome messaging size limits](https://developer.chrome.com/docs/extensions/develop/concepts/messaging)：扩展消息上限 64 MiB；项目 Native Host 自身限制为单帧 256 KiB，需按项目上限切小块。

因此已确认**不能从当前 DOM 或 activeTab 直接读任意 CDN 原始字节**。可行路径是对用户当前明确勾选的、公开 HTTPS 图源按需请求精确主机权限，扩展 worker 无凭据下载，再以校验分块传入本地应用；是否能取得真实 XHS/CDN 图片仍需登录态 QA 实测，权限不足或资源要求登录时诚实失败，不退回后台 URL 下载。

## 原型与当前协议契约

- 原型：[剪藏主界面与插件场景](./剪藏重规划界面原型.html)。这是交互/布局参考，功能实现仍需经过 AC 验收。
- Rust 与扩展 popup 当前均定义 `protocolVersion=12`，扩展 v0.9.0。正式与 DEV 包已分别生成至 `client/src-tauri/target/browser-extension-v0.9.0` 和 `client/src-tauri/target/browser-extension-dev-v0.9.0`；包检查覆盖 18 个运行文件及 integrity manifest。Native Host 单帧限制 256 KiB，版本不匹配须明确报错，不得静默降级。
- 既有 `inspirations` 是剪藏主对象，类型由 `materialType` 派生为账号/笔记/素材；顶部 `clipKind` 可被接收但以服务端推导为准。旧 URL 图片标记 `sourceKind=legacy_url`，扩展直传原图标记 `extension_bytes`。
- 新图像传输 action：`begin_capture_image_upload`、`write_capture_image_chunk`、`finish_capture_image_upload`、`fail_capture_image_upload`。所有 action 校验原 `requestId`、所选 `targetAccountId`、`expectedChannel` 和 `expectedWorkspaceId`；begin 声明位置、长度、MIME 与 SHA-256，write 声明位置和 offset，finish/fail 指明图片位置。`begin` 返回 `nextOffset` / `alreadyReady`；`write` 仅在 fsync 与 SQLite offset 更新后确认，已确认的重复块仅在字节一致时幂等 ACK；摘要、MIME/魔数、图像解码及本地原图/缩略图入库通过后才变为 ready。扩展按 Native Port 串行等待 ACK；弹窗每次 begin/write/fail 等待 15 秒，finish 等待 35 秒，Rust Native socket 对应允许 10/30 秒。遇超时先按原身份 lookup/begin 查 offset，不盲写或换 requestId。
- 原始块上限 64 KiB；正式读写边界仍为单图 25 MiB、单条剪藏累计 32 MiB、最多 12 张。Native Messaging 请求/回复外层分别保持 256/160 KiB；Rust app write 的 base64 字段上限为 88 KiB。
- `lookup_capture_request` 的 `imagesTotal` 为 payload images 长度与当前记录行数的较大值；`imagesReady` / `imagesFailed` 仅数当前账号、当前原 requestId 的逐图持久状态。恢复结果不累加计数，失败重试仍属于同一图。正文收藏和所有用户所选图片都已本地入库才可呈现“剪藏完成”。
- 主页笔记逐篇同步不再由“主页指标已勾选”隐式触发；仅 `profileNotesRequested=true` 发起，必须是主页事件，服务端保存 ref snapshot 和可恢复 outcome。普通账号主页剪藏默认不导入主页笔记。
- 旧剪藏沿用 `inspirations` 与原账号边界；旧 URL 图片保留显式的一次性补全入口，新扩展剪藏不新增常规后端 URL 下载。`profile_material` → 账号剪藏、`note_material` / `web_material` → 笔记剪藏、`image_material` → 素材剪藏；新建草稿仅接受笔记/网页剪藏。
- 当前桌面已把「剪藏」设为独立一级导航，按账号/笔记/素材分类；沿用既有剪藏对象与受管文件，并通过非级联关系引用现有榜样、选题、草稿和创作素材，不另建孤立文件存储。旧 URL 图的补全动作只适用于 `sourceKind=legacy_url`。
- 2026-10-05 隔离跨层回归新增 Native frame → Unix socket → Rust action handler → 临时 SQLite/本地 assets → lookup 全链用例：三张多块 PNG，1 张在部分写入后标失败并在原 requestId 下重传；中途回执 1/3 ready、1 failed，结束 3/3 ready；错误通道、工作区、账号与 requestId 均被拒；重开临时库后逐张原图字节一致。`native_host::tests::` 6/6、`cargo check --offline`、Rustfmt 与 diff check 通过。这是合成隔离证据，不是真实网站/浏览器验收。
- AC-68–77 的自动隔离验证只证明对应模拟链路；真实 XHS/CDN、Chromium/Edge 权限提示、原生 DEV/PROD、QA-A/QA-B 与应用重启操作单独记录，不可用 mock/build 代替。
