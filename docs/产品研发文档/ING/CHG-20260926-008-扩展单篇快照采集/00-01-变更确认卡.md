# CHG-20260926-008 扩展单篇快照采集

## 目标

在既有 N12 剪藏（周星星）链路上扩展「单篇快照」能力：用户在浏览器中打开目标页（自己的笔记或榜样笔记），点击扩展或在应用内点该条「刷新」，解析当前页 DOM，把标题、来源、互动等结构化快照落入本地库，为发布后监控、榜样分析与复盘迭代供数。

产品语义：**打开链接 + 本地解析 DOM ≈ 人肉看一眼当前页**；不做定时抓取、不提供批量刷新入口。

## 现状

- N12 最初链路为 `browser-extension/`（Native Messaging + `host/host.cjs` + Unix socket）→ Tauri `browser_capture.rs` 校验与激活账号盖章 → WebView 待确认队列；按用户 2026-09-27 最新授权，剪藏路径现已改为 Rust 校验后直接写 SQLite、成功后 ACK，旧队列只用于升级迁移；`requestId`/`dedupeKey` 幂等。
- 权限边界已定：仅 `nativeMessaging`、`scripting`、`activeTab`；无 cookies/history/host；无常驻 content script。
- D4（周星星）已锁定混合路线与风险分层：剪藏/单页读取低风险；大批量默认不提供；不自动提交；MediaCrawler 子模块不改。
- 榜样账号在 PC 有 `reference_accounts` 本地管理；发布后指标快照与「单篇刷新」能力尚未实现；移动端截图填数不在本 CHG。
- 参考对象（只读）：NOOMD 剪藏扩展（Native Messaging、manifest 版本对齐、固定扩展 ID、工作空间授权）；Beav（登录态页面采集 + 本地知识库）。不照搬其数据模型。

## 范围

1. **采集协议**：`BrowserCaptureEvent` 扩展 `kind`（至少 `clip` 既有、`note_snapshot` 自己笔记、`ref_snapshot` 榜样笔记）；`protocolVersion`；字段容错（缺失标 null，不编造数字）。
2. **快照字段**（最小集）：`sourceUrl`、`title`、`author`、`capturedAt`、`metrics{like,collect,comment}`（可空）、正文摘要、`requestId`；解析失败降级为 title/URL/正文文本，不整条失败。
3. **触发方式（强制克制）**：
   - 统一文案「**数据抓取**」+ 统一图标（CloudDownload）；覆盖笔记、主页、榜样等一切目标 URL。
   - 当前行为：仅**在浏览器打开该条链接**，由用户点扩展按钮解析当前页；手动测试阶段，不做加载后自动注入。
   - **不提供**「抓取全部/一键全抓/批量」任何入口。
   - **不做**定时、后台、队列连开标签。
4. **落库**：新增快照存储（如 `note_metric_snapshots` / `reference_snapshots`，或等价设计），与 `reference_accounts` 关联；按当前激活账号盖章；不采信任扩展传入的账号字段。
5. **入口**：榜样笔记/自己笔记的详情或列表条目上单条「刷新快照」；成功/失败有明确反馈。
6. **工程纪律**：manifest `version` 单一版本来源与 bump 规则；扩展 ID 与 Rust `EXTENSION_ID`、Native Host `allowed_origins` 一致；Native Messaging 不新开 HTTP 端口。
7. **QA**：隔离工作区验收；扩展 `check:browser-capture` 覆盖新 kind 与权限门禁。
8. **弹窗默认操作**：打开扩展后经 Native Messaging 查询当前激活账号的本地记录；已匹配自己的笔记、已跟踪榜样笔记/主页、本账号已收藏的笔记/主页或已有指标快照时默认进入「更新数据」，否则默认进入「收藏内容」。查询只预选操作页，不自动写入；用户可切页并同时执行两项。

## 非目标

- 不做「刷新全部/批量采集」入口；不做定时或无人值守抓取。
- 不做无登录爬虫、代理池、指纹对抗、打码、行为拟人化等绕检测能力；不承诺「防封」。
- 不做自动发布/自动互动；不改 `tools/MediaCrawler` 子模块。
- 不做视频笔记、评论区全量抓取、站内搜索爬榜。
- 不做移动端截图 AI 填数（后续独立切片）；不做云同步。
- 不做完整复盘看板/AI 洞察闭环（本 CHG 只保证快照数据进得来、可查询）。

## 用户反馈与对齐提案（2026-09-27，待确认）

用户指出：设置页的「复制路径」不便用于加载扩展；设置页版本与浏览器插件弹窗版本不一致，容易误解。截图作为当前界面现状证据，不视为产品指令。

### 已核实原因

- `project_extension_dir()` 默认拼接 `CARGO_MANIFEST_DIR/../../browser-extension`；`copy_extension_path()`、`open_extension_dir()`、`status()` 和安装结果目前直接使用该路径字符串，没有先解析为规范绝对路径。因此设置页会显示并复制带 `../../` 的路径。
- 设置页版本来自桌面端所选扩展目录的 `manifest.json`；插件弹窗版本来自 Chrome/Edge 当前实际加载扩展的 `chrome.runtime.getManifest().version`。桌面端目前没有读取浏览器已加载扩展版本的机制。
- 所以设置页现在显示的是“本机扩展目录版本”，不是“浏览器当前加载版本”。若浏览器仍加载旧目录/旧副本，两处版本可能不同；当前提示文案没有清楚说明这个区别。

### 本轮已实施（2026-09-27 · 根据用户复现）

- 扩展目录存在时先解析为规范路径；复制路径严格使用 canonical absolute path，状态展示、打开目录和安装提示共用规范目录。
- 复制成功 toast 改为「路径已复制」，不再携带完整路径；通用 toast 限制在视口内、允许长文本换行，并限制堆叠高度。
- 用户于 2026-09-27 确认 AC-12 与 AC-14 验收通过；其他浏览器链路验收不因此自动通过。
- `npm run build`、`cargo check`、`rustfmt --edition 2021 --check client/src-tauri/src/browser_capture.rs` 均通过；cargo 有 10 条其他既有 unused/dead_code 警告。本轮未跑测试套件，也未进行原生窗口验收。

### 其余建议的修正方向（等待用户确认后实施）

1. 将设置页版本明确标为“本机扩展包版本/待加载版本”，注明浏览器当前加载版本以扩展弹窗右上角为准；若两者不一致，提示在 `chrome://extensions` 或 `edge://extensions` 重新加载刚复制路径对应的目录。设置页不宣称已检测浏览器中的扩展版本。
2. 暂不新增跨进程的“最后一次插件上报版本”状态；它需要处理未连接、旧缓存和上报时间。若用户希望设置页直接显示浏览器实际版本，再单独确认是否需要该能力。

## 用户反馈与对齐提案（2026-09-27 · 提示溢出与保存链路）

用户指出：设置页右下角「路径已复制」提示内容超出提示框；并询问桌面端打开后插件是否即可保存、是否另有服务接口。截图只作为现状证据。

### 已核实现状

- 修复前，设置页将完整路径拼进 toast（`路径已复制：{path}`）；通用 toast 设有固定 `max-w-xs`，但路径文本没有强制断行。
- 没有单独的 HTTP 服务接口。扩展通过 Chrome/Edge Native Messaging 启动本机 `host.cjs`（按次启动的轻量转发进程），它再连接桌面端启动时创建的 owner-only Unix socket `~/.aichihongshu/browser-capture.sock`；数据库校验与写入在桌面应用内完成。
- 因此「应用开着」是必要条件，但不是唯一条件：浏览器扩展必须已加载、对应 Native Messaging 宿主清单已安装，应用 socket 正在监听，且当前激活账号已就绪。
- 当前 `BrowserCaptureBridge` 挂在全局 `App`，不要求停留在「灵感」页；但旧版 `browser-extension/README.md` 仍写着需停留在灵感页，和现代码不一致，后续文档同步时应更正。
- 连接状态 `ping` 只能证明应用 socket 可响应。旧捕获流程里 Rust 在 `app.emit` 成功后即回 `ok`，前端再异步写快照或加入待确认队列；所以旧版插件成功文案不是数据库已持久化的端到端确认。旧版收藏内容需用户确认后才成为已收藏素材。

### 本轮修复与验收情况

- 按用户再次复现，复制成功提示现改为「路径已复制」；通用 toast 增加视口内宽度约束、长文本任意位置折行及堆叠高度限制。
- 用户于 2026-09-27 确认路径复制与提示框验收通过（AC-12、AC-14）。

### 原待确认方向（最新指令已授权本轮实施）

1. 在设置说明与扩展状态提示中明确链路依赖：应用需运行，扩展与宿主需就绪；无需停留在某个业务页，但必须有当前激活账号。移除“必须停留在灵感页”的旧说明。
2. 用户于 2026-09-27 明确授权剪藏直接入库并以卡片状态展示，最新指令覆盖旧的待确认队列设计。本轮将浏览器收藏写入 SQLite 后再向 Native Messaging 确认；页面以“已收藏/已转草稿”状态标识，不再展示常规待确认区。数据快照保存仍由应用内结果提示确认，插件不把 socket 在线误称为入库成功。
