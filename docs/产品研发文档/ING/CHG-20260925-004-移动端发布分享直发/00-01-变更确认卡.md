# CHG-20260925-004 移动端发布分享直发

## 目标

移动端发布准备页支持「像系统相册分享那样」把关联图片一次带进小红书编辑器：唤起系统分享面板（多图），文案一并随分享带出；用户在小红书内完成最终发布。保留「导出到相册」为备用入口。

## 现状

- 发布准备页（`mobile/app/(tabs)/create/publish.tsx`）链路：复制文案到剪贴板 → 导出关联图片到独立相册 → 深链 `xhsdiscover://` 打开小红书；图片并不随跳转带过去，需在小红书内手动选图。
- 依赖：无 `expo-sharing` / `react-native-share`；RN 自带 `Share` 不支持文件。
- 图片路径：`ph://` / `file://` 混用，已有 `resolveLocalUri` 可统一解析。
- 设计书明文发布辅助形态为「复制文案、导出相册、跳转小红书」（`docs/移动端技术设计书.md` 8.3 / 10.3）。
- CHG-20260922-003 待决项「小红书分享 SDK 是否接入（保持人工交接）」由本变更以系统分享面板方案落地（不接 XHS SDK）。

## 范围

- 发布页主按钮改为系统分享面板直发：关联图片 resolve 为 `file://` 后一次唤起分享面板，payload 附带标题+正文+标签文案。
- 点分享时自动把全文写入剪贴板（兜底，真机验证 XHS 对「图+文」的接收情况）。
- 「导出图片到相册」保留为次级备用入口；「打开小红书」深链保留。
- iOS 优先实现与验证；Android 链路同 API 预留，验证后补。

## 非目标

- 不做小红书自动发布、无人值守、防封、批量采集。
- 不接小红书官方分享 SDK。
- 不做视频笔记、不做 Android 本轮验收。

## 已确认决定（用户 2026-09-25）

| 决定 | 选择 |
| --- | --- |
| 主路径 | 多图系统分享面板 + 文案一并带出 |
| 导出到相册 | 保留为备用入口 |
| 平台优先级 | iOS 优先，Android 后补 |

## 待决事项

- 真机验证：小红书分享扩展对「多图+文本」的接收行为（文案进正文 / 被忽略 / 仅部分图）。
- 若 iOS XHS 分享扩展忽略文案：保留剪贴板复制为正式兜底路径（不视为缺陷）。
- Android `ACTION_SEND_MULTIPLE` 与 XHS 接收行为后续切片验证。

## 2026-10-02 分享标题回归修复

用户反馈“分享的时候没带上笔记标题”，并明确要求未完成项继续交由子 Agent 实施。最新授权覆盖 9 月 26 日“正文不含标题”的旧决定：系统分享 message 和兜底剪贴板均包含标题、正文、话题，另保留分别复制标题/正文能力。系统 title 字段仅作为元信息，不依赖接收端读取它。AC-03/04 本轮重新待真机验收；不进行真实发布。

## 2026-10-04 发布准备页整理补充

用户授权沿用本 CHG 调整发布准备页。范围补充如下：

- 图片按笔记关联顺序展示，标出封面与图片总数。
- 正文默认展示摘要；完整文案按需预览。复制完整文案作为主入口，分别复制标题/正文收进次级操作。
- 分享主按钮固定在底部；原生多图路径明确为分享全部图片，单图回退路径先保存整组图片，再分享封面与文案，并在点击前说明需要到小红书补选其余图片。
- 原生多图面板启动失败时显示失败，不静默退成首图分享；相册导出与单独打开小红书仍保留为备用操作。
- 增加返回编辑入口和发布结果手动确认。分享面板关闭/返回只记录分享结果，不会自动把笔记状态改为已发布；只有用户明确确认已在小红书发布后才更新状态。

AC-07：打开发布准备页，图片顺序与笔记关联顺序相同，首张标记为封面并展示总数。
AC-08：默认只显示正文摘要；可查看完整文案，复制主入口复制含标题的完整文案，分项复制按需展开。
AC-09：原生多图路径携带全部图片；单图回退先成功保存全部图片再携带封面和文案，失败不继续伪装成多图分享。
AC-10：从分享面板或小红书返回后，发布状态保持待发布；只有显式确认“已在小红书发布”才将笔记状态改为已发布。

本补充不引入自动发布。系统分享接收标题/正文的实际行为、原生多图及回退路径仍待真机验收。
