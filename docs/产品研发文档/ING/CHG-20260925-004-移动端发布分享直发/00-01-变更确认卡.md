# CHG-20260925-004 移动端发布分享直发

## 目标

移动端发布准备页支持「像系统相册分享那样」把关联图片一次带进小红书编辑器：唤起系统分享面板（多图），文案一并随分享带出；用户在小红书内完成最终发布。保留「导出到相册」为备用入口。

## 现状

- 发布准备页（`mobile/app/(tabs)/create/publish.tsx`）链路：复制文案到剪贴板 → 导出关联图片到独立相册 → 深链 `xhsdiscover://` 打开小红书；图片并不随跳转带过去，需在小红书内手动选图。
- 依赖：无 `expo-sharing` / `react-native-share`；RN 自带 `Share` 不支持文件。
- 图片路径：`ph://` / `file://` 混用，已有 `resolveLocalUri` 可统一解析。
- 设计书明文发布辅助形态为「复制文案、导出相册、跳转小红书」（`docs/移动端技术设计书.md` 8.3 / 10.3）。
- CHG-20260922-003 待决项「小红书分享 SDK 是否接入（保持人工交接）」由本变更以系统分享面板方案落地（不接 XHS SDK）。

## 范围

- 发布页主按钮改为系统分享面板直发：关联图片 resolve 为 `file://` 后一次唤起分享面板，payload 附带标题+正文+标签文案。
- 点分享时自动把全文写入剪贴板（兜底，真机验证 XHS 对「图+文」的接收情况）。
- 「导出图片到相册」保留为次级备用入口；「打开小红书」深链保留。
- iOS 优先实现与验证；Android 链路同 API 预留，验证后补。

## 非目标

- 不做小红书自动发布、无人值守、防封、批量采集。
- 不接小红书官方分享 SDK。
- 不做视频笔记、不做 Android 本轮验收。

## 已确认决定（用户 2026-09-25）

| 决定 | 选择 |
| --- | --- |
| 主路径 | 多图系统分享面板 + 文案一并带出 |
| 导出到相册 | 保留为备用入口 |
| 平台优先级 | iOS 优先，Android 后补 |

## 待决事项

- 真机验证：小红书分享扩展对「多图+文本」的接收行为（文案进正文 / 被忽略 / 仅部分图）。
- 若 iOS XHS 分享扩展忽略文案：保留剪贴板复制为正式兜底路径（不视为缺陷）。
- Android `ACTION_SEND_MULTIPLE` 与 XHS 接收行为后续切片验证。

## 验收条件

| 编号 | 步骤 | 可观察预期 |
| --- | --- | --- |
| AC-01 | 发布准备页点「分享到小红书」 | 系统分享面板弹出，带出全部关联图片 |
| AC-02 | 在分享面板选择小红书 | 进入小红书编辑器，图片已带入 |
| AC-03 | 分享触发后查看剪贴板 | 全文（标题+正文+标签）已在剪贴板 |
| AC-04 | 分享 payload 文案 | 真机记录 XHS 是否自动填入文案；无论结果，复制按钮可用 |
| AC-05 | 点「导出图片到相册」 | 仍可按原链路导出到独立相册 |
| AC-06 | 用户取消分享面板 | 无报错、状态不误标为已导出 |

责任人：产品验收默认用户（真机）；实现与自动验证由执行者完成。
