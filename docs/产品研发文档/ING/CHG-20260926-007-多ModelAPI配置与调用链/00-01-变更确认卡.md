# CHG-20260926-007 多 Model API 配置与真实调用链：变更确认卡

## 目标

Model API 支持配置多套 Provider，并在 Tauri 桌面端可真实调用（文本流式），与 Agent CLI 双轨。

## 现状

- 仅单份 `AIModelApiConfig { enabled, baseUrl, model, visionModel, apiKey }`，存 localStorage（`client/src/lib/aiHost.ts`）。
- Tauri 下 AIPanel 禁用 model-api，只走 Agent CLI；Rust 端无模型 API 配置与调用能力。

## 范围

1. 应用级全局多 Provider 配置（参考 Noomd）：Provider 实例列表 + 每实例启用模型 + 全局默认 target。
2. 预置目录（DeepSeek / MiniMax / OpenAI / Anthropic）+ 兼容模板（OpenRouter / SiliconFlow / 智谱 / 火山方舟 / Ollama）+ 自定义。
3. API Key 存 Rust 本地 `app_settings`，与前端表单分离；读取视图脱敏。
4. 真实流式调用：OpenAI 兼容与 Anthropic 兼容两种 `kind`，复用 `local-ai://chunk|done|error` 事件契约。
5. 设置页「AI 与 Agent」的 Model API 区改为 Provider 列表管理；AIPanel 可选 Provider/模型发起对话。

## 非目标

- 不做 Provider fallback/自动切换、费用统计、Keychain、模型元信息目录（上下文/价格）。
- 不把本地 CLI 改造成 API Provider（CLI 仍是引擎）。
- 不删除旧 MiniMax 浏览器预览字段语义（保留折叠区）。
- 不实现图片输入/工具调用；visionModel 只作配置位，不宣称图片能力。

## 已确认决定（2026-09-26 用户确认）

1. 配置作用域：**应用级全局**。
2. 本期范围：**配置管理 + 真实调用链**。
3. API Key：**Rust 本地存储**。

## 待决事项

- 无。

## 验收条件

- AC-01：可添加/编辑/删除多个 Provider（预置 + 自定义），重启后配置仍在。
- AC-02：API Key 不出现在前端存储与日志；读取视图仅显示是否已配置/脱敏值。
- AC-03：「测试连接」对合法配置返回成功，对错误 Key/Endpoint 给出可读错误。
- AC-04：AIPanel 选择 Model API Provider + 模型发送文本，能流式收到回复并结束/报错正确。
- AC-05：取消进行中的 Model API 调用会停止输出。
- AC-06：`cargo test --lib`、`npm run build` 通过；用户 Tauri 原生验收 AC-01–AC-05。

## 文档影响

- 产品事实/技术事实/发布说明/用户手册：验收后补记「多 Model API 与真实调用」。
