## Tauri 开发态应用身份与正式应用对齐（2026-09-18）

- 用户问题：`npm run tauri` 启动的是 Cargo debug 进程，macOS Dock 以前显示 `aichihongshu`；正式打包应用显示 `爱吃红薯`，与 Noomd 的开发态/正式态名称不一致。
- 根因：本项目 `tauri.conf.json` 的 `productName` 已是 `爱吃红薯`，但 `client/src-tauri/Cargo.toml` 的 package/bin 仍是 `aichihongshu`。`tauri dev` 直接运行 Cargo debug 可执行文件，Dock 优先使用该进程名；只修改 `productName` 不能改变它。
- 实施：将 Cargo package 名和显式 bin target 统一为 `爱吃红薯`，设置 `default-run = "爱吃红薯"`；保留 `[lib] name = "aichihongshu_lib"`，因此 `main.rs` 的库调用和现有 Rust 模块不变。Cargo.lock 已同步更新。
- 追加修复：用户实机启动时进程立即退出。macOS 崩溃报告显示旧 Tauri 2.10.3 / Wry 0.54.4 在 WebKit 初始化阶段触发系统 `CFRelease() called with NULL`；对照 Noomd debug 产物确认其使用 Tauri 2.11.2 / Wry 0.55.1，因此同步更新锁文件到 Tauri 2.11.2、tauri-runtime 2.11.3、tauri-runtime-wry 2.11.4、Wry 0.55.1 及配套依赖。
- 验证：`cargo metadata --manifest-path client/src-tauri/Cargo.toml --no-deps --format-version 1` 确认 package/default-run/bin target 均为 `爱吃红薯`；`cargo check --manifest-path client/src-tauri/Cargo.toml --bin '爱吃红薯'` 与 `CARGO_TARGET_DIR=client/src-tauri/target/tauri-dev cargo build --manifest-path client/src-tauri/Cargo.toml --bin '爱吃红薯'` 通过，产物内含 Wry 0.55.1；`git diff --check` 通过。遵照用户此前要求，未启动或控制 Tauri，Dock 名称与窗口恢复需用户下一次运行 `npm run tauri` 后实机确认。
- 交接：如果 Dock 仍显示旧名称，先完全退出旧开发进程再重新运行；macOS 可能缓存正在运行的旧进程标题。正式 bundle 的 `productName`、图标和 identifier 未改动。
