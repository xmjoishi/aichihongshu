## 3. 阶段 A 盘点结果（2026-09-16）

### 3.1 当前仓库事实

- Tauri 目前只是桌面壳和打包版 Python 托管器：`client/src-tauri/src/lib.rs:1-128` 在 release setup 中查找 `uv`，再启动 `uv run python -m app.server --port 8765`；没有业务 command、SQLite State 或 Rust 领域模块。
- 前端所有数据访问仍经 `client/src/lib/api.ts:1-170` 的 `API_BASE = http://127.0.0.1:8765`。`client/src/components/BackendGate.tsx:1-100` 启动时轮询 `/health`，离线时阻断整个页面。
- `client/src-tauri/tauri.conf.json:6-44` 的开发/构建命令和 bundle 资源仍包含 Python 应用、crawler、MediaCrawler、`pyproject.toml` 与两份 `uv.lock`。`client/scripts/prepare-tauri.mjs` 也把这些 Python 资源当作打包前置条件。
- 仓库根目录没有 `package.json`；Tauri 脚本目前仅在 `client/package.json`，因此从根目录执行 `npm run tauri` 尚未成立。
- `app/server.py` 只负责初始化 DB、挂载 REST router 和静态资源；业务责任分布在 `app/routers/*.py`、`app/modules/*`、`app/services/*`。桌面功能实际覆盖图库、笔记、人设、榜样账号、账号池、经验库、设置、分析、AI、爬虫和发布。
- `app/db/schema.py` 与 `app/db/connection.py` 维护 SQLite `data/app.db`、增量迁移和账号池/浏览器目录兼容逻辑。`items`、`notes`、`reference_accounts`、`my_profile`、`account_pool` 等字段和多账号归属不能由启动改造顺手重写。
- `app/mcp/server.py` 是独立 stdio MCP 入口，直接访问 Python 业务和数据库；`app/cli.py` 是独立 CLI。两者本次不擅自删除或改语义。
- 移动端已使用自身 SQLite 和模型请求实现，本次聚焦桌面，不顺带重构 `mobile/`。

### 3.2 NOOMD 可借鉴事实

- `noomd/src-tauri/src/lib.rs` 以 Tauri commands + `State` 管理 Rust SQLite 连接和本地文件能力；`noomd/src-tauri/src/db.rs` 使用 `rusqlite`（bundled）建库/迁移。
- NOOMD 的 `src-tauri/src/agent_cli.rs` 提供本地 `claude`、`codex`、`opencode` 检测，运行时使用受限参数、JSONL/stream 解析、会话 ID、取消和硬超时；这可作为本项目 AI CLI 适配层的边界参考。
- NOOMD 的 `src-tauri/src/native_messaging.rs` + `integrations/noomd-browser-extension/` 采用浏览器扩展 `activeTab`/`scripting`/`nativeMessaging`，只向已授权工作空间写入剪藏结果；Native Host 使用长度前缀 stdio，重新计算内容摘要，并不导出 Cookie 或浏览器用户目录。
- NOOMD 的扩展实现是“网页剪藏”，没有小红书登录、采集或发布能力；不能据此宣称已验证本项目的浏览器方案。
- NOOMD 的 Markdown/`.noomd` 工作空间和本项目 `data/app.db` 的业务模型不兼容。可借鉴宿主边界、命令组织、凭据/会话安全和文档恢复机制，不能直接复制其表结构或假设数据可互读。

### 3.3 阶段 A 结论

- P0 必须先把“启动”和“本地核心数据通路”从 FastAPI 解耦；只删 `BackendGate` 或只改启动脚本会留下大量 HTTP 404/连接失败，不算去 Python。
- P0 需要以 Rust 本地层承接已明确的基础 CRUD 和文件路径读取，再逐页切换前端 adapter。AI、爬虫、发布是独立异步/外部能力，不能在未完成迁移时静默删除。
- `npm run tauri` 的根目录体验可先由根 `package.json` 转发到 `client`，但该脚本必须配合 `client` 的 Tauri 配置一起验证，不能把它等同于 Python 依赖已经清零。

### 阶段 B：P0 独立启动和本地业务

- 目标结构：React → Tauri commands → Rust 业务/存储层 → SQLite、本地文件。
- 将本地核心功能及其实际依赖迁移到 Rust，范围以阶段 A 清单为准，不能只迁移页面外壳。
- 移除桌面启动中的 Python/FastAPI 拉起、8765 健康等待及已迁移功能的 HTTP 依赖。
- 根目录提供 `npm run tauri`，同时启动前端开发环境和 Tauri。
- 明确数据库版本、迁移事务、旧数据读取、素材路径、账号隔离和失败恢复策略，保护已有用户数据。
- 如 D1 获确认，未迁移采集/发布入口显示明确状态；否则不得用功能禁用代替既有能力迁移。

验收：不预先启动后端、不要求 Python/uv/MediaCrawler 环境；单命令打开真实桌面窗口；本地核心流程完成“创建/修改 → 保存 → 切换页面 → 关闭重开”且数据保持；记录启动日志和进程依赖证据。此里程碑不等于所有功能去 Python 已完成。

### 阶段 C：P1 AI 双入口

- 参考已核实的 NOOMD 实现，设计统一的模型服务和本地 CLI 适配边界。
- 支持配置、能力识别、流式输出、取消、超时、错误反馈；区分文本与图片等能力，不假定所有 CLI 都支持。
- 本地 CLI 缺失或未登录时给出可操作提示；不得成为应用启动依赖。
- 凭据安全存储；命令参数与用户输入分离，不把敏感信息写入日志。

验收：至少一个配置的模型服务与一个约定 CLI 完成真实请求；验证取消、失败和重启后配置恢复；无 Python 回退路径。
