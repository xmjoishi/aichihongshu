## 1. 目标与边界

方向：清爽、清晰、适合长时间创作。用中性灰白画布保持内容可读，白色工作区域承载卡片与编辑，红色突出主要操作，黄色点缀灵感；品牌规范中的米白 `#FFF8F3` 保留给 Logo/品牌专属区域，不铺满整个应用画布。

本次覆盖 `client/` 桌面端：应用框架、看板、图库、笔记列表与编辑器、灵感、数据、榜样、账号人设、账号池、设置，以及弹窗、通知、加载、空态和错误态。浏览器预览保持兼容，但验收以 Tauri 为准。

不包含：移动端与官网改版、重画 Logo、换编辑器/图表/路由技术栈、数据库迁移、自动发布策略、AI Provider 或浏览器控制实现。不要因 UI 改版删除未迁移能力，也不要把依赖旧服务的操作标成已支持本地离线。

Read Set：品牌规范、当前 CHG、`client/src`、必要的 `client/src-tauri` 只读能力核对。后续 Write Set：`client/src` 的主题、共享组件、页面与必要的前端验证文件、当前任务文档；只在验证实际需要时调整前端测试配置。Rust/API 数据契约变更回到架构任务对应阶段处理。

## 3. 品牌与主题规格

### 3.1 颜色

前三项来自已确认品牌规范，其余为本计划的 UI 衍生候选，实施时通过实际对比度测量微调，不改 Logo 原色。

| 语义 token | 浅色候选 | 深色候选 | 用途 |
| --- | --- | --- | --- |
| brand | `#FF2442` | `#FF2442` | 品牌识别、装饰、强调图形 |
| inspiration | `#FFC94A` | `#FFC94A` | 灵感标记；搭配深色文字，不用黄字配白底 |
| canvas | `#FAFAFA` | `#18181B` | 应用底色；米白仅用于品牌专属区域 |
| surface | `#FFFFFF` | `#231F20` | 卡片、编辑区域、弹窗 |
| surface-muted | `#F4F4F5` | `#3F3F46` | 次级分区、悬停底色 |
| text-primary | `#18181B` | `#FAFAFA` | 正文及标题 |
| text-secondary | `#71717A` | `#A1A1AA` | 辅助信息，不能整页用浅灰 |
| border | `#E4E4E7` | `#52525B` | 容器分隔；交互控件轮廓另设更强 token |
| action-primary | `#FF2442` | `#FF6B81` | 主按钮底色；浅色配白字，深色配深色字 |
| selected-bg | `#FFF0F2` | `#4A1D27` | 导航/筛选选中背景，配可读文字及非颜色标记 |

`brand` 与 `action-primary` 分离：不默认认为 `#FF2442` 配小号白字达标。主按钮、hover、pressed、focus、disabled 的前景/背景均实测。正文对比度以至少 4.5:1、大字至少 3:1、必要控件边界和焦点指示至少 3:1 为本项目验收目标。

成功、警告、错误、信息使用独立语义色和图标/文字，不借品牌红表达所有状态；黄色灵感徽标与警告标记使用不同图标和文案。图表不得只靠红绿区分，搭配标签/线型。

Logo 使用当前 `/logo.png` 对应的最新纯白底生产图形，深色模式仍保留白底容器，不反色、不滤镜、不用旧 SVG 替代、不自动重导出图标。

### 3.2 主题行为

- 设置 → 外观：浅色、深色、跟随系统，默认跟随系统；浅色呈现暖白品牌方案。
- 保存应用级主题偏好，建议使用独立版本化 key `aichihongshu.appearance.v1`；不存进账号业务数据，不覆盖 `hdr_display`。
- 在 React 首次渲染前读取偏好并设置 `data-theme`、`color-scheme`，防止深色启动白闪；存储不可用时回退系统且不阻塞启动。
- 仅“跟随系统”模式响应系统主题变化，手动选择不被系统覆盖；重启保持，切换账号不重置。
- 主题覆盖 Portal、Toast、输入、滚动条、图表 tooltip、编辑器及空态；不对整个页面使用 invert/filter，也不改变素材图片色彩。

### 3.3 排版与密度

- 逻辑 CSS 尺寸建议：正文 14–16px，辅助信息 12–13px，页标题 24–28px，统计数字 28–32px；操作标签避免当前侧栏 10px。
- 间距采用 4/8/12/16/24/32；卡片内边距 20–24px，圆角 12–16px，按钮/输入圆角 8–10px，阴影仅用于浮层或层级区分。
- 常用控件高度 36–40px，图标按钮至少 32px，触控场景目标 44px；内容不靠大量空白制造层级。
- 侧栏展开态默认约 176px，可拖动调整至 160–288px，保证品牌区与导航标签单行；图标+文字横排并区分账号内导航与全局设置；提供约 64–72px 折叠态及 Tooltip。窄窗口优先自动折叠，保留导航可达。
- 顶栏 48–56px；主内容边距 24px，窄窗口 16px。统计四列→两列；编辑侧栏在空间不足时改抽屉。不改原生标题栏和窗口控制。
- 动效建议 120–180ms，仅用于状态反馈；尊重减少动态效果偏好，避免持续闪烁、弹跳或自动随机换内容。

## 4. 操作与页面方案

### 4.1 应用框架与看板（首个交付切片）

首屏顺序：页标题“运营看板”与“新建笔记”主操作 → 紧凑账号摘要 → 四个等高指标 → 待处理行动和最近笔记。

- 顶栏账号选择器为唯一全局当前账号入口；页面必要说明可保留账号名，但不重复展示角色、连接徽章与完整简介。
- 指标建议保留图库素材、全部笔记、草稿、已发布记录。草稿是总数子集，卡片不暗示四项互斥；已发布仅代表现有本地状态，不代表平台实时结果。
- 指标点击进入对应页面/筛选；只有真实支持的筛选才能提供点击态，无对应能力时保持静态展示。
- 账号卡缩为头像/名称/简介摘要/已有资料数据；长简介展开查看，未知值显示“暂无数据”而非 0。
- 待处理项来自真实数据，例如“37 个素材尚未关联笔记”；这是关联状态，不能擅自改称“从未使用”。提供可用的图库入口。
- 最近笔记展示标题、中文状态、更新时间和继续编辑/查看入口；不展示原始数据库字段，不生成假趋势。
- 移除顶栏重复计数和 prompt 创建入口前，确保看板/笔记的新建入口已经承接现有 `createLocalDraft` 能力。编辑写入尚不可用时，创建成功进入可用详情并明确保存能力边界，不伪装完整创作链路。
- 本地状态入口显示摘要，展开后查看刷新和诊断；数据库路径只在明确展开的诊断区域展示，不用悬浮即显示完整路径。

### 4.2 图库

- 固定页头：标题、总数、搜索、筛选、导入主操作；网格卡片统一图片比例、标题、标签和分析状态。
- 点击主体查看详情，选择框用于批量选择，菜单用于更多操作；避免卡片点击与选择冒泡冲突。
- 选中后出现批量操作条，明确当前账号、选择数量与作用范围；保留现有选择数据语义。
- 导入/分析显示进度、成功/失败数量及失败项原因；只有现有接口能保证安全重试时提供逐项重试，不在此计划新增持久任务引擎。
- 返回列表恢复搜索、筛选与滚动位置；切换账号清空选择，按账号隔离视图状态。

### 4.3 笔记列表、编辑与发布助手

- 列表统一状态标签（全部、草稿、待发布、已发布）、搜索与排序；保留既有发布时间排序口径。
- 编辑页：标题/正文为中心，素材与 AI 辅助可折叠；顶部固定返回、保存状态、保存、下一步。常用动作可见，删除等低频危险操作进更多菜单。
- 统一状态机：未修改 → 待保存 → 保存中 → 已保存 / 保存失败。只有收到成功响应才显示“已保存”，失败保留内容并提供重试。
- 复用现有自动保存逻辑，验证多次快速修改的响应顺序；旧请求不能覆盖新输入或把新输入误标为已保存。
- 路由返回、账号切换和窗口关闭涉及未保存修改时，提供保存后继续/放弃修改/取消；保存不可用或失败不得继续关闭。若原生关闭拦截需要新增 Rust/权限配置，单独列依赖，不能声称浏览器拦截等于原生已保护。
- 支持 Cmd/Ctrl+S 保存，键盘提示按平台显示；不覆盖输入法组合输入或文本编辑快捷键。
- AI 输出先预览/编辑再采用，不静默覆盖正文；不扩展现有 AI 执行权限。
- 保留“发布助手”“确认已发布”“自动发布”的区别，不合并成语义模糊的一键操作。“确认已发布”表示用户标记；自动发布必须依据实际结果，结果不明时提示核查，不能自动再次提交。

### 4.4 其余页面

| 页面 | 优化重点 | 保持的语义 |
| --- | --- | --- |
| 灵感 | 黄色用于灵感标签；固定候选卡片；用户点击换一批才更换内容；采用结果有明确反馈 | 不恢复随机渲染循环，不自动写入笔记 |

## 5. 通用交互契约

- 每个可操作组件覆盖默认、悬停、按下、焦点、禁用、进行中、失败；每个数据页覆盖首次加载、空数据、筛选无结果、加载失败、已有内容刷新。
- 骨架屏遵循真实布局；刷新保留旧内容并标明正在刷新；失败显示原因摘要与重试，不清空为“暂无数据”。
- 长任务说明正在做什么；取消按钮只在能力实际可取消时出现，不把停止 UI 等待标成任务已取消。
- 防止重复提交；成功后刷新当前账号的关联列表/统计；捕获操作发起时账号，不让晚到响应更新另一个账号页面。
- Toast 用于短反馈，表单错误贴近字段，持续失败使用页面内提示；错误不能只闪一下消失。
- 弹窗具有标题、焦点圈定、Esc 取消及关闭后焦点恢复；破坏性操作默认焦点不落在确认按钮。输入错误不关闭弹窗。
- Tooltip 不作为唯一操作名称；图标按钮提供可访问名称，Tab 可到达全部主要操作，当前导航提供语义标记。
- 未迁移能力保持入口。明确标注“此操作仍需旧服务”，给出可执行下一步；若进行中、缺少选择等条件导致禁用，说明具体原因，不借改版永久禁用功能。

## 8. 停止条件与收尾

只停止受影响步骤，其他独立 UI 工作继续：

1. 需要变更数据库 schema、账号归属、保存/发布契约或新增权限：记录依赖，回到架构计划对应阶段。
2. 需要删功能、清理账号会话或修改用户数据库/素材：不执行，说明具体需求和替代方案。
3. 文件出现并发修改或品牌源被更新：重读当前差异和品牌规范，先协调冲突，不回滚他人改动。
4. 模拟/浏览器通过而原生失败：保留失败记录，不标成验收完成。

验收后落点：产品事实更新主题和交互能力；技术事实更新 token/偏好存储/组件入口；用户手册更新外观与实际操作；发布说明仅写已验收变化且标明未发布；完成记录与 ING 索引更新真实阶段。UI 完成不等于去 Python 架构任务完成。
