## 1. 目的与边界

本项把桌面端当前每个操作的可用边界写成可核对的矩阵，并提供一个不会连接项目正式 `data/app.db` 或 `assets/` 的固定 QA 工作区。QA 入口只生成 `.qa/desktop-workspace/`，不复制浏览器 Cookie、登录态、正式素材或用户数据库。

本项不迁移业务 CRUD，不改变已有数据语义，不修改 `tools/MediaCrawler`、移动端、Noomd 或正式数据。读取可用、保存可用、旧服务可用和桌面产品验收通过分别记录，不能相互替代。

## 4. 隔离 QA 入口

固定工作区：`.qa/desktop-workspace/`（已加入 `.gitignore`）。生成内容包括：

- `data/app.db`：只含固定的 `QA-A`（id `101`）和 `QA-B`（id `202`）两个 operation 账号。
- `fixtures/qa-a-desk.png`、`fixtures/qa-b-balcony.png`：两个 1×1 占位图，不引用正式 `assets/`。
- `browser_profiles/QA-A`、`browser_profiles/QA-B`：空目录，仅用于验证路径归属，不放登录态。
- `.aichihongshu-qa-workspace`：安全标记；Rust 仅在 debug 模式接受带标记的 QA 路径。

命令均从仓库根目录执行：

```sh
npm run qa:prepare   # 幂等准备固定 QA 数据；输出 workspace/database 实际路径
npm run tauri:qa     # 准备后启动 Tauri，显式设置 AICHIHONGSHU_QA_WORKSPACE
npm run qa:reset     # 仅删除并重建固定 .qa/desktop-workspace
```

`qa:prepare` 已有数据库时保留 QA 中的编辑结果，适合关闭后重开验证持久化；需要恢复初始 A/B 样本时才执行 `qa:reset`。脚本拒绝覆盖存在但没有 QA 标记的数据库，也拒绝操作固定目录之外的路径。

## 5. 固定 A/B 样本与复位说明

初始状态：active account 为 `QA-A`（101）。每个账号各有 1 条素材、1 条草稿、1 条人设；A 的对象 ID 为 item `1001` / note `1101`，B 的对象 ID 为 item `2001` / note `2201`。图片路径均为 QA 工作区内相对路径。

建议每项后续任务复用以下顺序：

1. 执行 `npm run qa:reset`，记录输出的 `workspacePath` 和 `databasePath`。
2. 执行 `npm run tauri:qa`；在运行状态或日志中核对路径包含 `.qa/desktop-workspace/data/app.db`。
3. 在 QA-A 查看“QA-A 书桌角”和“QA-A 草稿”，切换到 QA-B 后只应看到“QA-B 阳台角”和“QA-B 草稿”。
4. 对当前项写入一个带 `QA-A`/`QA-B` 前缀的临时标题或正文，关闭并再次执行 `npm run tauri:qa`；确认写入留在 QA 工作区且另一账号不可见。
5. 失败或需要重置时终止 Tauri 后执行 `npm run qa:reset`；该命令只针对固定 `.qa/desktop-workspace`，不删除 `data/app.db`、`assets/`、`data/browser_profiles/` 或其他目录。

账号切换不是登录行为，QA fixture 不包含 Cookie、Token、浏览器用户目录内容或真实账号信息。若后续任务需要文件导入，使用 `.qa/desktop-workspace/fixtures`，不要选择正式 `assets/`。

## 12. N07 AI 会话与运行元数据边界

`useAIStream.ts` 将历史迁移到 `localStorage`，键包含数据库身份、账号和笔记/素材对象；最近消息限量、单条内容限长。每次发送建立 `runId`，本地 Tauri 还把账号、对象、Provider、状态、时间和脱敏错误写入 `ai_runs`，完成后的助手文本写入 `ai_run_artifacts`，不写完整提示词或凭据。本地 Tauri 通过 `localAi.ts` 先探测 CLI，再用 Rust 事件接收真实 stdout；abort 调用 Rust 终止对应子进程。应用重新打开时遗留的 `running` 会被标记为 `interrupted`，不会自动续跑；`retry` 由用户显式触发。真实 Tauri 重启回收、原生产物回读和真实登录态仍待后续验证。

## 13. N08 AI 提案与来源边界

`client/src/lib/aiProposal.ts` 为每次采用记录账号、笔记、字段和 `baseVersion`。`Notes.tsx` 采用前校验当前版本；版本或账号不一致时标记冲突、提示重新生成并保留原文。AI 面板显示来源边界提示：当前笔记、选中素材和已注入经验可作为上下文，只有带正文的真实来源才可用于摘要；外部 URL 无正文不会被伪造为摘要。提案差异视图和按数据库/账号/笔记隔离的限量本地历史已落地；真实 Provider 来源回读留待后续。

## 11. N06 Provider/CLI 探测边界

`scripts/check-cli-capabilities.mjs` 只执行 `claude --version`、`codex --version`、`opencode --version`，每个命令有 2 秒超时，输出不包含环境变量、凭据或完整命令参数。Tauri 的 `probe_local_ai_providers` 同样只做版本探测；`providerCapabilities.ts` 和运行面板将文本、图片、工具和取消能力默认标为未知/不可用，安装成功不等于认证或文本能力已验证。真实调用使用无 shell 的固定非交互参数，失败/空输出显示实际错误；图片/工具仍未启用，Provider 配置不写入全局文件或业务库。

## 14. N09 单篇笔记创作台边界

`Notes.tsx` 编辑器顶部显示当前账号和保存版本/失败状态；素材预览、正文和 AI 辅助面板属于同一笔记对象。AI 面板在窄窗口默认收起，用户可通过顶部入口显式打开或关闭；Prompt 面板提供收起入口。未引入新的编辑器或三栏固定布局，原生窗口尺寸、主题和关闭重开回读仍待产品验收。

## 15. N10 灵感收集与选题转化边界

`browserCapture.ts` 负责消息边界校验，Tauri 灵感页通过 `inspirations` SQLite 表保存标题、来源 URL、观察正文、收藏理由和状态。来源 URL 为空时允许手工灵感，非 `http(s)` 链接拒绝；正文为空明确显示“待补正文”。显式“转为草稿”只创建当前账号本地草稿并记录 `noteId`，不会自动标记采用或调用旧 HTTP；浏览器原有生成链路保持不变。真实抓取、来源快照和删除源资料后的完整历史引用留待后续。
