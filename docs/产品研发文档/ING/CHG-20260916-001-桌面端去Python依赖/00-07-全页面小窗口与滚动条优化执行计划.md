### 第四轮实现记录（2026-09-21，滚动条按引擎分流 + 显隐改类名驱动）

- 用户反馈“滚动条直接消失了，滚动的时候也消失了”：第三轮移除标准属性后，WebKit（macOS WKWebView）进入 ::-webkit-scrollbar 自定义路径，但 WebKit 不会因宿主状态（:hover、类名变化）重新应用 ::-webkit-scrollbar-thumb，静止透明的滑块从此无法浮现。
- 用 Playwright Chromium 做像素级验证定位真相：Chromium 支持类名触发滑块重绘（.is-scrolling 生效），但不支持宿主 :hover 触发（矩阵测试悬停 0 像素）；WebKit 连类名触发也不可靠（用户实测）。另注意 Playwright headless 默认 --hide-scrollbars 会让截图不渲染滚动条，验证时必须 ignore_default_args 去掉该参数。
- 最终策略按引擎分流，由 index.html 内联脚本在首次渲染前设置 data-scrollbar-engine（检测失败不设置时同样回落原生，fail-open）：
  - “webkit”（macOS WKWebView / Safari）：不命中任何自定义滚动条规则，交还系统原生浮层滚动条（滚动时浮现、悬浮于内容上、停止自动隐藏），不再定制。
  - “chromium”（Windows WebView2 / Chrome）：自定义静默浮现式。静止滑块全透明；.is-scrolling / .is-scrollbar-hover 浮现约 32% 对比；8px 命中条 + 2px 透明边框，视觉约 4px。
  - Firefox：@supports not selector(::-webkit-scrollbar) 块内标准属性 thin + 状态显色，新增 .is-scrollbar-hover。
- App.tsx 监听器扩展：新增委托 pointerover/pointerout（捕获、被动），findVerticalScrollable 自指针位置向上找最近可纵向滚动容器加 .is-scrollbar-hover，指针离开窗口或移出可滚动区时移除；卸载时清理全部类与引用。
- 自动验证：npm run build（tsc + vite）通过；git diff --check 通过；构建产物 CSS 的像素级回归验证通过（chromium 模式：静止=0、is-scrolling>0、is-scrollbar-hover>0、命中条 8px；webkit 模式：宽度=auto 自定义规则未命中，原生渲染不随类变化）。测试临时脚本已清理。
- 本轮修改文件：`client/index.html`、`client/src/index.css`、`client/src/App.tsx` 及本文档。待用户原生验收：macOS 滚动时出现系统原生浮层滚动条；Windows/Chrome 下为约 4px 静默浮现细滑块。

## 3. 统一设计规则

### 滚动条与滚动区域

1. 默认可见滑块约 4 CSS px，中性色低对比，轨道透明、圆角；滚动容器 hover、focus-within 或实际滚动时增强可见度。（2026-09-21 定稿：按引擎分流——WebKit 用静态低对比细滑块约 16% 常驻、状态加深为渐进增强（其宿主状态/类名重绘滑块不可靠，静止不可设全透明）；Chromium 用静默浮现式，显隐由共享 JS 加类驱动（.is-scrolling / .is-scrollbar-hover），宿主 :hover 重绘不可用；Firefox 用标准属性。浅/深主题使用各自 token，不使用品牌色滑块。）
2. 保留滚轮、触控板、键盘与拖动；不要全局 scrollbar-width:none。横向图片条可保留已有隐藏策略，但不能将必要表格滚动完全隐藏。
3. 优先 CSS；若必须监听滚动，使用共享实现、被动监听和清理，避免高频 React 更新。具体显隐效果受 WebKit 和系统滚动条设置影响，原生验收确认，不承诺完全覆盖系统偏好。
4. 页面只有一个主要纵向内容滚动区；独立抽屉/编辑器可各自滚动。给 flex 子级补齐必要 min-h-0/min-w-0，不用全局 overflow-x:hidden 掩盖被裁掉的控件。

### 可用宽度与状态保留

1. 页面内部优先基于容器实际宽度判断密度；外壳才使用窗口断点。容器查询可满足时优先 CSS；只有列数或面板模式确实需逻辑判断时才用共享 ResizeObserver。
2. 外壳建议 <960px 自动呈现 64px 图标侧栏；>=960px 恢复用户手动折叠/宽度偏好。自动模式不写入用户偏好；小窗口展开使用临时覆盖导航，不写回折叠偏好（2026-09-21 按用户反馈取消“选择菜单项后自动收回”，导航后保持展开，由展开/收起按钮控制）。
3. 内部布局参考：内容宽 >=960px 可并排，640–959px 紧凑重排，<640px 单主区；最终门槛按各页主区最小可用宽度确定，记录实测值，不机械套用同一阈值。
4. 顶栏优先保留当前账号与数据状态；数量等次要信息折叠，长账号名截断且可查看完整值。标题和主要按钮不逐字折行；按钮使用不换行文字，操作组整体换行或收进“更多”。
5. 侧栏低高度时导航区独立可滚动，底部设置/账号池可达。页面间距可由 24px 收到 12–16px，正文维持现有阅读大小。
6. 详情/AI 窄屏改覆盖抽屉，有明确关闭入口；模态抽屉管理焦点、Escape 和遮罩，关闭恢复触发点焦点。宽窄模式切换不通过 key 重挂载编辑器或 AI 组件，不中断生成、不清除输入和选中。
7. 弹窗受 viewport 宽高限制：标题/关闭与底部动作可达，正文 min-h-0 内滚动；危险操作的确认语义不变。悬浮批量栏为其下方内容预留空间。

### R03 图库必须实现的细节

- 用户选择列数是偏好上限；建议卡片最小宽度约 140px、间距约 12px。实际列数 = min(偏好列数, 容器可容纳列数)，下限 1；具体值可按实测微调。
- 存储偏好值，不将临时自动减少后的列数回写。窗口放大或详情关闭后恢复偏好允许的列数。
- 滑块/列数提示不得显示“8列”却实际仅有3列而无解释，可写“3列（偏好8列）”或等价简洁反馈。
- 主区不足以承载卡片和工具栏时，详情覆盖展示；多选栏“已选 N 张”、合并生成、删除、取消不能逐字竖排；次要批量操作可进入更多。
- 详情和批量模式同时存在时操作清晰可达；遮罩不允许误点底层。保留已有缺失素材、回收站、不可用能力提示。

### R04 创作页面必须实现的细节

- 小窗口不强塞预览+正文+AI 三栏；提供“预览”和“AI 助手”入口，正文保存入口持续可达。
- 切换展示模式不得清除未保存标题/正文/标签、AI 历史、生成中状态或灵感生成结果。
- 低高度时上方提示可紧凑或折叠，正文仍有可编辑空间；素材条保持合理缩略图宽度，不被压成细条。
- 灵感抽屉取消硬性超过可用空间的最小宽度，底部重新生成/保存操作可达；保留正在生成、失败、空结果和已保存反馈。

## 5. 验收矩阵与编码

以 CSS viewport 为测量标准：800×600、1024×768、1280×800；额外 800×500 检查低高度。原生窗口外框与 WebView 高度不同，应记录 window.innerWidth/innerHeight。每个路由在前三种尺寸检查基本展示，低高度检查导航、表单、编辑器和全部弹窗。深浅主题均检查；宽窄连续拖动检查临界点，不只测端点。

| 编码 | 步骤 | 可观察预期 |
| --- | --- | --- |
| AC-01 | 对照全部12个路由，逐页记录尺寸、主题、普通/空/加载/错误与展开状态 | 无漏页；逐项填实际结果，未执行不能写通过 |
