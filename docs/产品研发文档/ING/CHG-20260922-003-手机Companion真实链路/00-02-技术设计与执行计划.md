# 手机 Companion 真实链路：技术设计与执行计划

## 1. 代码入口

| 层 | 路径 | 职责 |
| --- | --- | --- |
| PC 服务端 | `client/src-tauri/src/pc_harness.rs` | 局域网 HTTP、配对令牌、任务 API |
| PC 数据 | `client/src-tauri/src/db.rs` | `companion_tasks` 表与任务读写；复用素材导入/草稿 |
| PC 命令 | `client/src-tauri/src/lib.rs` | `pc_harness_status/start/stop/rotate_token` |
| PC 设置 UI | `client/src/pages/Settings.tsx` + `client/src/lib/local.ts` | 开启/停止、地址与令牌展示、PC 本地 QR 生成 |
| 手机契约 | `mobile/services/pcHarness.ts` | 客户端类型与请求（与服务端 DTO 对齐） |
| 手机任务 UI | `mobile/app/(tabs)/create/harness.tsx` | 上传、轮询、取稿、回填 |
| 手机配置 UI | `mobile/app/(tabs)/profile/pc-harness.tsx` + `mobile/services/pcHarness.ts` | 扫码、地址校验、健康检查后保存；保留手动配置 |

## 2. 协议（`/api/mobile/v1`）

- 鉴权：`Authorization: Bearer <pairingToken>`；失败 401。
- `GET /health` → `{ ok, service:"pc-harness", protocolVersion:"1", accountId? }`
- `POST /companion/tasks` JSON body：
  ```json
  {
    "topic": "string?",
    "accountId": 1?,
    "clientTaskId": "uuid?",
    "photos": [{ "filename": "a.jpg", "mimeType": "image/jpeg", "dataBase64": "..." }]
  }
  ```
  至少一张照片或非空主题。返回 `CompanionTask`。
- `GET /companion/tasks/:taskId` → `CompanionTask`
- `GET /companion/tasks/:taskId/draft` → `CompanionDraft`（`noteId/title/body/tags/itemIds/version/source`）
- `POST /companion/tasks/:id/publish-receipt` → `PublishReceipt`，返回更新后的 `CompanionTask`

说明：从 multipart 调整为 JSON+base64，便于与 `LocalImageImport` 对齐并降低 RN `FormData` 差异；两端同步修改，契约以本文为准。

### 状态机

`queued` → `processing` → `ready` | `failed` | `cancelled`

本批创建时同步完成导入与建稿：成功即 `ready`，失败写 `error` 为 `failed`。`clientTaskId` 非空时先查重，命中则返回原任务（幂等）。

## 3. 责任边界与安全

- 仅用户显式「开启手机连接」后 `TcpListener::bind("0.0.0.0:port")`（默认 18765，可配置）；停止即 drop listener。
- 新生成的令牌由系统安全随机数生成器产生 32 字节随机值；仅在 Harness 设置中展示/复制，存储在本地 app_settings（不进业务日志）。
- 配对二维码只在 Harness 运行且有 LAN 地址时显示，由 PC 内存中的 QR 编码器本地生成；payload 包含类型、版本、LAN base URL、协议版本和 Bearer 令牌，不上传到二维码服务。
- 手机只接受本项目版本 1 配对码，限制目标为私有/链路本地 IPv4 或本地域名；无凭据、路径、查询串或片段。先鉴权调用 `/health` 且协议匹配，再保存到手机 SecureStore。
- 令牌轮换后原二维码立即失效；二维码应只由可信手机扫描。相机权限只在用户发起扫码时请求。
- 不暴露 Tauri invoke、任意路径、shell；只处理上述 5 个端点。
- 上传：类型/大小限制（JPEG/PNG/WebP，单张 ≤ 12MB，最多 9 张）；走 `import_local_image` 同等校验。
- 账号：创建时冻结 `account_pool_id`；后续读写只认任务上的账号，不跟随 UI 激活账号变化。
- 发布回填：只记录用户回执（status/noteUrl/message），不发起平台请求；`confirmed` 才可关联平台证据。

## 4. 数据

```sql
CREATE TABLE IF NOT EXISTS companion_tasks (
  task_id TEXT PRIMARY KEY,
  client_task_id TEXT,
  account_pool_id INTEGER NOT NULL,
  status TEXT NOT NULL,
  topic TEXT,
  item_ids TEXT NOT NULL DEFAULT '[]',
  note_id INTEGER,
  title TEXT,
  body TEXT,
  tags TEXT NOT NULL DEFAULT '[]',
  content_version INTEGER,
  publish_status TEXT,
  publish_note_url TEXT,
  publish_message TEXT,
  error TEXT,
  created_at TEXT,
  updated_at TEXT
);
CREATE INDEX IF NOT EXISTS idx_companion_tasks_client
  ON companion_tasks(account_pool_id, client_task_id);
```

## 5. 实施顺序

1. S0 文档与目录（本 CHG）
2. S1 DB 迁移 + 任务读写
3. S2 `pc_harness.rs` HTTP 服务 + lib 命令
4. S3 设置页开启/停止、令牌展示与本地二维码
5. S4 手机契约 JSON 对齐 + harness 任务 UI 轮询/回填 + 扫码验证配对
6. S5 隔离 QA 自动检查 + 实施记录/检查点
7. S6 交用户原生/真机验收（不代操作正式发布）

## 6. 停止条件

- 出现账号串写、正式数据误写、未鉴权可访问 → 立即停写并回滚该步。
- 真实平台提交不做；出现需要自动发布的需求先暂停对齐。
- 无法绑定端口/权限不足时明确报错，不静默降级为无鉴权服务。
