# PC 工作台整合与统一 AI：变更确认卡

任务：CHG-20260921-002
状态：实施中
日期：2026-09-21
基线：1f4865a（执行前工作区基线提交）

## 目标

将桌面端导航收敛为概览、素材库、灵感、笔记、账号五个业务入口；保留账号池和快速切换；将搜索改为 LOGO 下的全局入口；将发布并入笔记、数据并入账号、榜样并入灵感。建立统一 AI Copilot 的浮窗、侧栏和独立页面三种展示方式，并支持 Model API 与 Agent CLI 两类接入，为后续手机端 Harness 和 Agent 串联提供稳定任务边界。

## 范围

- PC 导航、路由兼容、模块内视图整合和全局搜索入口。
- AI 会话/运行/上下文的复用，现有页面 AI 入口迁移，设置中的 AI 与 Agent 配置。
- 账号池保留、账号作用域隔离、灵感与笔记关联、发布状态语义保留。

## 非目标

- 本轮只实现手机端 PC Harness 配置、配对令牌存储和客户端 API 契约占位；不实施 PC 监听服务、完整局域网任务闭环、虚拟账号/共享资产、无人值守发布或大批量采集。
- 不修改 `tools/MediaCrawler` 子模块，不删除旧 Python CLI/MCP 入口，不提交正式账号或用户数据。
- 不将 AI 展示形态切换误作自动执行授权；最终发布仍需用户确认。

## 本轮补充对齐结论（2026-09-22）

- 全局 AI 入口采用页面右下角常驻圆形 FAB。它在概览、素材库、灵感、笔记、账号、账号池和设置等页面均可见；点击后进入统一 AI 宿主，默认打开浮窗。FAB 只负责打开入口，不代表已授权自动执行。
- 页面内已有的 AI 入口继续保留：灵感页的“灵感梦工厂”、笔记编辑中的 AI 辅助、榜样/参考账号分析等入口仍服务于当前页面的即时任务。它们必须复用统一会话、运行和上下文协议，不再各自创建一套 AI 状态。
- AI 重构先完成“当前页上下文协议”，再拆分页面与 AI 的硬嵌套。上下文至少携带 `accountId`、页面/模块标识、对象类型与 ID、对象版本、选中素材、未保存编辑状态和来源；发起运行时冻结账号与对象作用域，页面切换只更新可见上下文，不改写运行中的任务。
- 页面内入口通过上下文适配器调用统一 AI 宿主；在协议完成前，不把页面内容直接复制进宿主，也不为每个页面新增专用 AI 服务。拆分硬嵌套后，页面入口、右下角 FAB、侧栏、浮窗和独立页仍指向同一会话/运行。
- 账号池继续作为工作空间级切换入口保留。右下角 FAB 显示当前账号上下文；切换账号时隐藏旧账号内容，运行中的任务固定原账号，不能将提案或结果静默应用到新账号。

### AI 工作区补充结论

- 侧栏顶部增加一级 `运营 / AI` 工作区切换；不增加截图中仅用于样式参考的“对话 / 工作”二级 Tab。内部仍保留 Ask/Agent 两种执行语义。
- AI 工作区会话历史按当前账号隔离；会话在浮窗、侧栏和独立页之间复用同一个 session ID；空会话只有发送首条有效消息后才进入历史。
- 浮窗全屏操作直接进入 AI 工作区并定位到当前会话；AI 工作区提供新建会话、会话历史和当前会话主区域，进入后隐藏右下角 FAB。
- Composer 采用本地化方案：当前上下文、结构化 `@` 引用、页面 `/` 命令、Ask/Agent、Model/Agent CLI 和发送控制；移除无明确语义的“收集”开关。Ask 只读问答，Agent 先计划并对写入动作要求确认。
- 独立页收紧顶部信息，CLI provider/model 采用自定义搜索选择器；本地 CLI 通过增量事件流显示输出。
- Logo 不在侧栏重复展示；macOS 使用标题栏 Overlay，让收纳/展开控制与账号切换入口统一位于跨全窗口、与红黄绿窗口控制同一行的紧凑顶栏左侧，运行状态与资源计数位于顶栏右侧，形成左右分区；顶栏位于侧栏和主内容之上。`运营 / AI` 工作区仍位于左侧栏，展开时显示图标与文字；窄侧栏下工作区和页面选中态使用 40×40 圆角方形按钮，并以品牌色边框强化选中状态。

## HDR 图片关闭效果修复（2026-09-27）

- 调查发现原“关闭 HDR”只对图片应用亮度/饱和度滤镜，没有要求支持的 WebKit 将 HDR 媒体映射至 SDR，因此 HDR 显示器上仍可能使用扩展动态范围。
- 修复：关闭时对图片和视频设置 `dynamic-range-limit: standard`，开启时恢复 `no-limit`；保留旧 WebView 的滤镜回退。
- AC-16：关闭时支持该 CSS 属性的运行环境将图片/视频限制在标准动态范围；开启时允许 HDR 显示；切换即时生效并保留本地偏好。

## 笔记页签滚动位置恢复（2026-09-27）

- 发现笔记滚动位置只按账号共用一个存储键，页签间互相覆盖；恢复也可能早于笔记数据加载。
- 修复：侧栏返回笔记时恢复上次使用的列表/瀑布流/发布准备视图；按状态页签和视图分别保存滚动位置，在筛选偏好和笔记内容加载后恢复。
- AC-18：从其他页面返回笔记时恢复上次使用的笔记视图；离开某状态页签或视图后再返回，恢复对应滚动位置；账号之间视图和滚动位置互相隔离。
- AC-19：从任一工作台页面离开后返回，恢复同一账号、路由/查询页签及页面滚动区域的位置；账号/页面间不串位置；异步内容加载后仍恢复，且不覆盖恢复目标或干扰用户主动操作。
