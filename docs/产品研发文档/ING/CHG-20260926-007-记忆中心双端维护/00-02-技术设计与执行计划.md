## 1. 数据模型（Rust `LocalDb` / SQLite）

### 1.1 `memory_entries`（L3 事实记忆）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | |

| origin | TEXT CHECK pc/mobile | 端归属池 |

### 1.3 L0/L1 系统规则

- L0 常量在 Rust 中定义，只读。
- L1 默认常量在 Rust 中定义；覆盖存 `app_settings` 键 `memory_l1_override`（全局，非账号）。
- 查询返回 `{ l0, l1Default, l1Active, l1IsOverride }`；保存覆盖 / 重置为默认。

## 2026-09-27 用户确认的数据权威与缓存契约

- 手机本地记忆与提示词是手机池唯一事实源；手机负责查看，手机端操作与 PC 写穿操作最终都由手机本地执行并落库。
- 同一 PC 账号仅由一部手机作为手机池来源。手机记忆页进入时、手机本地记忆变更后，以及 PC 写穿命令在手机落库后，均上传手机完整快照更新 PC 的 `origin=mobile` 缓存；成功推送全部条目后，PC 清理不在快照中的缓存，空快照也清空缓存。
- 对账接口只接收手机上行的 PC 缓存 ID 清单并返回删除计数，不向手机返回 PC 缓存内容，也不允许 PC 记忆页写手机池。
- PC 侧缓存需镜像确认状态、启用位、提示词适用场景；手机离线删除仍以 tombstone 上行清理对应远端缓存，配对目标变化时旧 PC 的 tombstone 保留待重连处理。
- 手机 AI 只注入启用、已确认、有效记忆；经验提示词按 `applyTarget` 匹配 compose/chat。PC AI 仅查询 `origin=pc`。
- 此契约覆盖本文旧有“PC 维护手机池”和“冲突最后写入”描述。

## 2026-09-27 PC 实时写穿手机池（用户最新确认，覆盖只读缓存交互约束）

- `origin=mobile` 的手机本地 SQLite 仍是唯一事实源；PC Rust Harness 持有短时命令 broker，不对手机缓存直接开放写操作。
- 手机 App 前台通过已配对 Harness 轮询命令，并在本机验证远端 ID 属于当前 PC 配对后，调用现有手机记忆服务完成 SQLite 操作，再上传手机快照并回传操作回执。
- PC 发起方等待手机回执；仅手机本地保存与缓存同步成功后刷新 PC 列表。手机离线/后台或超时不保留待执行写命令；PC 不乐观改缓存。
- `pc_harness_mobile_connection` 轻量 Tauri 命令按前台轮询心跳报告当前账号手机在线状态，控制手机池操作入口；在线期间支持记忆和经验提示词新增、编辑、启停与删除。
- 协议新增 `GET /api/mobile/v1/memory/commands/next` 与 `POST /api/mobile/v1/memory/commands/:id/result`；命令操作名/载荷为受限联合类型，不暴露任意数据库写入或路径操作。

## 2026-10-02 手机规则与经验扩容

手机默认写作经验/输出规则共用 `mobile/services/writingRules.ts`；`ai.ts` 组装请求，记忆页只读展示，避免 UI 与实际规则两份文本漂移。用户 L2 不做自动覆盖，PC L1 不下发手机。L2 上限 5000，手机/PC JS 使用 Unicode code points 计数，Rust 使用 chars；PC 注入保留 5000 字。编辑页和聊天页读取手机经验失败应进入错误处理，不使用空字符串静默降级。

生成通过 `expo/fetch` 消费 Anthropic/OpenAI SSE；逐行缓冲跨块 UTF-8，处理末行与错误，JSON 兼容响应只消费当前请求。mock 测试不连接真实服务，不使用凭据或用户数据库。真实设备/provider 与 PC 写穿验收由 AC-11–13 覆盖。

## 2026-10-03 PC 查看手机实际系统规则

`SystemRulesSection` 按 origin 分派独立组件，避免手机分区保留 PC 编辑状态/调用。手机 query key 包括端、账号、在线状态，禁用离线读取与自动重试，不持久缓存。Harness broker 新增只读 `readSystemRules`，手机运行时从 `writingRules.ts` 返回正文、source/version/readAt/accountId/editable:false，回执增加可选 `systemRules`，兼容旧写操作。手机读取分支不执行 applyCommand、数据库变更、完整快照同步或变更事件。Rust 命令/账号匹配检查与 PC 回传账号/字段校验共同防止串账号；旧手机返回不支持时展示错误，不读取 PC 默认作为兜底。

## 2026-10-04 移动端记忆与连接页 UI、经验快照补充

### 移动端信息架构

- 记忆页以「记忆 / 写作经验」为两个主分区；新增入口放在导航栏右侧并跟随当前分区打开独立编辑弹层。系统规则通过次级只读链接打开独立弹层，不占主分区页签。
- 记忆列表支持本地内容/主体/来源搜索及全部、待确认、使用中筛选。候选显示「AI 暂不使用」，确认按钮只表示确认事实，不暗示自动启用；仅确认且有效、启用的条目显示为使用中。候选的主要操作保留确认/忽略，编辑、启停、删除和标记过时收进更多菜单。
- 写作经验显示启用数/每池 10 条上限、账号范围和出稿/对话适用场景。达到上限后，新增项默认为停用并可保存；启用已有停用项前由界面提示先释放名额。
- PC 连接页突出扫码配对；地址、令牌和设备名放在默认折叠的高级手动配置内。连接状态区分未配对、未保存、已保存待检测、最近检测成功及失败；测试同时核对 `ok`、服务标识与协议版本。敏感令牌继续只进手机安全存储。

### 写作经验缓存整批事务

- 主代理新增 Rust `db/mobile_prompt_snapshot.rs` 整批写入事务与 PC Harness `POST /api/mobile/v1/memory/prompts/snapshot` 路由，health 能力标识 `mobilePromptSnapshot`。手机同步先提交整批写作经验快照；成功后才清除对应 tombstone/替换 PC 副本，不能在快照成功前逐条更新或清墓碑。
- 不支持新能力的 PC 明确要求更新并重启，不降级到旧的逐条提示词写接口。记忆条目仍走原有同步链路；手机仍是手机池唯一事实源，失败不影响手机本地数据。
- 核验由主代理报告：`mobile_prompt_snapshot` 定向单测 2 项、core 全量 64/64、core `--all-targets` strict Clippy、Tauri lib strict Clippy、路由定向 1/1、`mobile/tests/memory-snapshot.cjs` 和 `mobile/tests/system-rules-command.cjs` 均通过。真机 Harness 行为仍待验收。
