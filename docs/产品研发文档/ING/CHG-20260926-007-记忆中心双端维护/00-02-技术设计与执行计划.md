## 1. 数据模型（Rust `LocalDb` / SQLite）

### 1.1 `memory_entries`（L3 事实记忆）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | |
| account_pool_id | INTEGER NOT NULL FK | 账号隔离 |
| origin | TEXT CHECK pc/mobile | 端归属池 |
| kind | TEXT CHECK positioning/expression/fact/event/content_history | 对应 Roadmap §6.1 层次 |
| content | TEXT NOT NULL | 记忆内容 |
| subject | TEXT DEFAULT '' | 主体（如：门后置物架） |
| scope | TEXT DEFAULT 'account' | 作用域标记 |
| source | TEXT DEFAULT '' | 来源描述 |
| source_type | TEXT CHECK user/ai_draft/import/sync | 来源类型 |
| occurred_at | TEXT NULL | 发生时间（可空，保留原始精度） |
| confirm_status | TEXT CHECK candidate/confirmed/rejected/outdated | 确认状态 |
| valid_status | TEXT CHECK valid/invalid | 有效状态 |
| replaced_by | INTEGER NULL FK memory_entries | 替代关系 |
| created_at / updated_at | TEXT | |

索引：`(account_pool_id, origin, confirm_status, valid_status)`。

状态机：`candidate → confirmed | rejected`；`confirmed → outdated`（可带 `replaced_by`）；`rejected/outdated` 不可再迁回候选（要重录新建）。

### 1.3 L0/L1 系统规则

- L0 常量在 Rust 中定义，只读。
- L1 默认常量在 Rust 中定义；覆盖存 `app_settings` 键 `memory_l1_override`（全局，非账号）。
- 查询返回 `{ l0, l1Default, l1Active, l1IsOverride }`；保存覆盖 / 重置为默认。

## 2026-09-27 用户确认的数据权威与缓存契约

- 手机本地记忆与提示词是手机池唯一事实源；手机负责查看，手机端操作与 PC 写穿操作最终都由手机本地执行并落库。
- 同一 PC 账号仅由一部手机作为手机池来源。手机记忆页进入时、手机本地记忆变更后，以及 PC 写穿命令在手机落库后，均上传手机完整快照更新 PC 的 `origin=mobile` 缓存；成功推送全部条目后，PC 清理不在快照中的缓存，空快照也清空缓存。
- 对账接口只接收手机上行的 PC 缓存 ID 清单并返回删除计数，不向手机返回 PC 缓存内容，也不允许 PC 记忆页写手机池。
- PC 侧缓存需镜像确认状态、启用位、提示词适用场景；手机离线删除仍以 tombstone 上行清理对应远端缓存，配对目标变化时旧 PC 的 tombstone 保留待重连处理。
- 手机 AI 只注入启用、已确认、有效记忆；经验提示词按 `applyTarget` 匹配 compose/chat。PC AI 仅查询 `origin=pc`。
- 此契约覆盖本文旧有“PC 维护手机池”和“冲突最后写入”描述。

## 2026-09-27 PC 实时写穿手机池（用户最新确认，覆盖只读缓存交互约束）

- `origin=mobile` 的手机本地 SQLite 仍是唯一事实源；PC Rust Harness 持有短时命令 broker，不对手机缓存直接开放写操作。
- 手机 App 前台通过已配对 Harness 轮询命令，并在本机验证远端 ID 属于当前 PC 配对后，调用现有手机记忆服务完成 SQLite 操作，再上传手机快照并回传操作回执。
- PC 发起方等待手机回执；仅手机本地保存与缓存同步成功后刷新 PC 列表。手机离线/后台或超时不保留待执行写命令；PC 不乐观改缓存。
- `pc_harness_mobile_connection` 轻量 Tauri 命令按前台轮询心跳报告当前账号手机在线状态，控制手机池操作入口；在线期间支持记忆和经验提示词新增、编辑、启停与删除。
- 协议新增 `GET /api/mobile/v1/memory/commands/next` 与 `POST /api/mobile/v1/memory/commands/:id/result`；命令操作名/载荷为受限联合类型，不暴露任意数据库写入或路径操作。
