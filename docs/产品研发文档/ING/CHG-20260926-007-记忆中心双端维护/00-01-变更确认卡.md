# CHG-20260926-007 记忆中心双端维护：变更确认卡

## 目标

1. 两端都提供「记忆」维护入口：查看、编辑、删除、新增、候选确认。
2. 记忆范围合并：经验库数据 + B05 结构化记忆 + 用户经验提示词。
3. 提示词分层落地：L0/L1 系统经验只读可重置；L2 经验提示词用户自由维护。

## 现状

- PC「数据 → 经验库」（`KnowledgeTab`）只有规律/样本/灵感开关，无事实/事件/来源/确认状态。
- 移动端无记忆入口；Harness 文案写死「历史记忆仍由 PC 端管理」。
- 提示词：系统骨架/格式规则/默认方法论硬编码于 `useAIStream.ts`、`app/routers/ai.py`、`prompt_builder.py`、`mobile/services/ai.ts`（三端不一致）；用户只能改人设字段与快捷指令（`prompt_configs`）。
- 方案对齐文档：`docs/产品研发文档/产品规划/2026-09-26-记忆中心双端维护方案对齐.md`。

## 范围

按对齐文档批次实施；本 CHG 覆盖批次一至四：

1. **批次一**：记忆数据模型与服务（Rust/SQLite）：L2 经验提示词 + L3 事实记忆 CRUD、候选状态机、`origin`（pc/mobile）字段；L0/L1 只读查询与 L1 恢复默认。
2. **批次二**：PC 记忆中心页（收编经验库与快捷指令）；池切换；AI 注入按 L0–L3 顺序，默认只注入本端池。
3. **批次三**：手机「记忆」页（只维护手机池）+ 手机本地记忆存储 + Harness 同步契约。
4. **批次四**：候选确认流完善（AI 提炼入候选、来源追溯、替代/过时）与双池/账号隔离回归。

## 非目标

- 不做素材/笔记/账号数据的跨端同步。
- 不自动导入历史聊天；不自动确认 AI 提炼内容。
- 保留 PC Harness 的 Companion task API；手机记忆仍以手机为事实源，PC 通过在线手机写穿修改，手机落库后更新 PC 缓存；不在此 CHG 内合并移动端与桌面端数据库。
- 不启用向量检索；检索仍为结构化过滤 + 全文。
- 不改旧 Python 路径的发布/爬虫行为。

## 已确认决定（2026-09-26 用户确认）

1. 范围：**合并记忆中心**（经验库 + B05 事实记忆 + 经验提示词）。
2. 数据归属：**双池分端**，物理各自本地；手机只能维护手机池；PC 可维护 PC 池，手机连接并同步时也可维护手机池。
3. 首期操作：**查看 / 编辑 / 删除 / 新增 / 候选确认**。
4. 系统经验：**L0/L1 只读展示 + 可恢复默认**；用户层自由写。
5. 经验提示词形态：**多条可开关条目**（标题 + 内容 + 启用 + 适用范围）。

## 2026-09-27 数据权威规则修订（用户确认，覆盖旧双向维护约定）

1. 手机记忆池以手机本地数据为唯一事实源；手机提示词/记忆只在手机端查看和修改。
2. 同一 PC 账号仅由一部手机作为手机池来源；每次同步以上传的手机完整快照对账 PC 缓存，手机空快照也会清理旧缓存。
3. PC 记忆池仍以 PC 本地数据为事实源；PC 不提供手机池写入口，也不把手机池数据下发回手机。
4. PC 可保存手机池只读缓存；缓存损坏或被清理时可由手机端重建。同步对账仅回传删除数量，不向手机返回 PC 缓存内容。
5. 两端 AI 各自默认只使用本端事实源；PC 的手机池缓存不进入 PC AI 记忆上下文。

## 2026-09-27 PC 实时维护手机池规则（用户最新确认，覆盖上条的只读约束）

1. 手机仍是手机池唯一事实源；PC 不能直接写自己的 `origin=mobile` 缓存作为最终结果。
2. 手机 Harness 在线且手机 App 在前台时，PC 可发出新增、编辑、启停、删除手机记忆/经验提示词的操作；手机执行本地 SQLite 写入并回执，PC 缓存仅在手机执行成功并完成上行后更新。
3. 手机离线、App 在后台或回执超时，PC 禁用手机池编辑，并明确显示手机连接状态；不排队离线修改，也不在 PC 缓存上做乐观写入。
4. 传输通过已配对的 Bearer Harness 命令轮询完成；PC 发出的命令限定于记忆池操作，手机以自己的本地 ID/配对 PC 的远端 ID定位条目。仍遵守同一 PC 账号只配对一部手机。
5. 设备实时可达语义为手机记忆页所在 App 处于前台并持续连接 Harness；执行成功以手机本地持久化回执为准，PC 刷新缓存后再刷新视图。

## 验收条件

- AC-01：记忆条目（L3）可新增/查看/编辑/删除；字段含内容、类型、subject、source、source_type、发生时间、确认状态、有效状态、替代关系、origin。
- AC-02：候选可确认/否定/过时；确认状态迁移合法（候选→确认/否定；确认→过时），非法迁移被拒。
- AC-03：L2 经验提示词可增删改、开关、设适用范围（全局/账号 · 出稿/对话/全部）；列表按池隔离。
- AC-04：L0/L1 系统规则可只读查询；L1 覆盖可保存、可一键恢复默认；L0 不可改。
- AC-05：账号隔离：A 账号的记忆/经验条目不出现在 B 账号查询结果。
- AC-06：`origin` 隔离：列表可按 pc/mobile 过滤；手机池条目在手机未连接时 PC 不提供可写入口；在线编辑必须手机落库并回执后才更新 PC 缓存。
- AC-07：`cargo test`（db 层单测）与 `npm run build` 通过；Tauri 命令可调通。
- AC-08（批次二，用户原生）：PC 记忆中心页完整维护流可用；AI 注入顺序 L0–L3 且默认不串池。
- AC-09（批次三，用户真机）：手机记忆页本地维护手机池；手机前台在线时 PC 可通过手机命令写穿修改；手机离线可独立维护，PC 禁用手机池写入口；PC 不直接改写手机池缓存。
- AC-10（批次四）：AI 提炼入候选不自动确认；删除后新任务不再引用；历史产物标注已撤回来源。
